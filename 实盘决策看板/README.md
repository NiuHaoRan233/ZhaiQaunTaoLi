# 实盘决策看板

## 项目目标

建立独立的盘中决策工作台，以实时盘口为核心，直观展示每个模型的判断、信号和动作，为后续“模型提出建议、人工检查后决定是否放行”的实盘工作方式做准备。

本项目与策略规则文档分开维护。策略模型仍由现有做市引擎负责；本目录只管理看板产品、交互、审批流程及其实现。

## 长期产品定位

系统的最终目标是把行情数据、模型决策、账户状态、风险检查、委托执行和成交回报连接成一条自动运行链路。程序启动并通过启动前检查后，正常交易过程不要求人工逐笔批准；看板作为这条链路的控制面板，集中展示各模型和账户的运行状态，并提供启停及盘中风险控制入口。

控制面板需要明确区分不同强度的操作，不能把它们合并成一个含义模糊的“停止”按钮：

- 暂停模型决策：停止生成新建议，但不擅自处理既有挂单或持仓。
- 禁止新增风险：允许减仓和补回客户底仓，不再增加额外库存或方向暴露。
- 撤销活动委托：撤掉指定模型、账户或全局范围内尚未完成的订单。
- 紧急停止：阻断新委托并撤销活动委托；是否主动平仓必须由独立、明确且经过验证的规则决定。
- 盘中风控：监控库存、现金、亏损、行情数据新鲜度、账户连接、委托回报和模型异常，并按已配置规则降级或停止。

所有控制动作都必须具有明确作用域、二次确认、操作者、时间、触发原因和执行结果记录。看板显示“已停止”之前，必须以执行端和账户回报确认实际状态，不能只依据浏览器按钮状态。具体止损阈值、触发后只停新单还是撤单、是否以及如何平仓，当前仍属于待确认规则，不在看板层自行推断。

## 核心视图

- 以债券实时盘口为底图，叠加模拟盘当前运行策略的挂单；模型增删跟随模拟盘，看板只对观察下拉框执行固定的易读排序，不另设模型名单。
- 明确显示每张模型订单的方向、价格、数量、建立时间、当前状态及第一顺位或排队信息。
- 实时显示挂单、撤单、改价、部分成交和完整成交，并解释动作原因。
- 为每个模型单独展示动态合理价与合理区、趋势、关键证据、库存、客户底仓缺口、当前信号、拟执行动作及不行动原因。
- 保持模型身份独立，不把不同模型的挂单、仓位、成交或收益合并。

## 人工放行流程

未来的目标流程为：模型生成可解释的订单建议，建议进入待检查状态，由用户批准、拒绝或修改。系统应同时保留模型原始建议和人工处理结果，便于区分模型判断与人工覆盖。

每次建议至少记录模型ID、产生时间、因果行情快照、方向、价格、数量、理由、有效期限、人工决定及决定时间。等待期间若盘口、合理区、库存、风险边界或原始信号发生实质变化，旧建议必须失效并重新生成，不得直接执行过期建议。

## 当前安全边界

当前阶段实现可视化、模拟批准以及手动接管的干运行追价闭环。行情 SQLite 始终只读，手动执行器只在内存中生成纸面订单，服务固定声明券商委托关闭，不发送真实委托。手动动作仅追加到本地忽略的`../半自动手动交易/runtime/manual_takeover_audit.jsonl`，不会写行情账本。任何真实交易连接都属于后续独立阶段，需要另行授权、设计和安全验收。

## 待确认事项

- 盘口展示深度、刷新频率和每个模型的颜色标识。
- 多债券采用同屏、分页还是独立窗口。
- 人工批准时是否允许修改价格、数量和有效期。
- 建议超时及行情变化导致自动失效的具体条件。
- 盘中提醒方式以及收盘后的审批和执行复盘格式。

## 当前原型

已提供本地 Web 看板原型，直接读取父项目 `data/zhaiquant.sqlite3` 的实时纸面账本：

```powershell
.\start_dashboard.cmd
```

浏览器打开 `http://127.0.0.1:8765`。当前页面把 G三峡EB2 与 26江铜EB 同屏固定展示，不再依赖债券切换。每只债券分别显示最新价、紧凑的近一小时分时、动态合理区、放大的五档盘口、买卖价差和市场成交增量。分时线采用近一小时有效的正数最新成交价；开盘前或首笔成交前 MiniQMT 返回的零价快照不会进入曲线和纵轴范围。市场成交从上到下按时间正序排列，最新一笔位于列表底部；列表刷新后默认定位到最新成交。成交方向沿用通达信式 `B` / `S` 简写（B红、S绿）；方向仍是本地推定，不是交易所 Level 2 主买主卖标志。

默认观察下拉框最上方的最新模型，通过紧凑下拉框切换模拟盘当前运行的其他模型；两只债券盘口只叠加当前模型的活动纸面挂单。实时模型名单读取 SQLite 最新模拟盘运行会话保存的 `config_json.maker_paper`，账户、委托和成交读取同一数据库的正式纸面账本。下拉框固定按“第一顺位、排队、超级捡漏”的分支顺序展示，同一分支内版本从新到旧；当前四模型矩阵默认显示第一顺位2.63，其后为2.52、1.50和1.37。该展示排序不改变模拟盘实际运行矩阵。这样看板展示的是模拟进程实际加载的名单，而不是看板硬编码名单，也不会把同日早些时候已退出但仍按要求保留的账户误当成当前模型。历史2.6 r3仍显示“第一顺位2.6”，新`maker_priority_v2_63_candidate`显示“第一顺位2.63”。

第一顺位1.49继承1.47建立的静默参考权限：在14:45以后、至少600秒无新成交、买卖一价差至少0.40元且当前盘口仍包住最后盘中工作中枢时，才把看板从昨收退化显示纠正为“盘中成交中枢（静默期低置信保留）”。可视区间限制在该中枢上下0.20元内；这是只读展示对策略参考的同条件复现，不会写数据库或反向改变模型订单。

挂单按真实价格顺位贴在对应买卖档右侧，用紧凑的 `B/S + 委托价 + 数量 + 极限价` 标注显示：买单追加“上限”，表示订单创建时冻结的最高可接受买价；卖单追加“下限”，表示最低可接受卖价，鼠标提示显示完整名称。例如买一137.000、改善一厘买单137.001、最高买价137.235时，气泡显示`B 137.001 1,000张 上限137.235`。边界只读取订单创建时保存的模型输出，不由看板按当前行情重算；旧订单当时未保存时明确显示“未记录”。五档内部的插档价也归入对应档位，只有真正低于买五、高于卖五或越过正常被动报价范围的委托才单列为“盘口外（超出五档）”。盘口纵向留白同时表达价格距离：同侧相邻档位价差不足0.05元时不加空档，达到0.05、0.20、0.50和1.00元时，额外留白依次为0.25、0.5、0.75和1个盘口行高；留白对应价差达到0.20元时，在空档右侧显示精确到厘的价差金额，字号随空档高度平缓地从14像素增至20像素。买一与卖一之间使用独立尺度，同样四档依次为0.75、1、1.5和2个行高，不足0.05元时仍保留0.5个行高容纳价差文字；中央“买卖价差”字号也随高度从12像素动态增至24像素。两只债券会根据卖盘内部留白和各自买卖价差高度在卖五上方补齐空间，使两条买卖价差横线的中心始终处于同一水平，同时保证黄色价差区域直接连接卖一与买一，不在其中插入黑色对齐空白；盘口外委托条固定占位，不会破坏中线对齐。档位化间距避免细小价格变化造成布局持续抖动。

下方动作流水按债券一分为二，G三峡EB2固定在左、26江铜EB固定在右，各自独立滚动并只展示本债券的挂单、撤单、买卖成交及订单号；挂单与撤单合并为“委托（挂/撤）”筛选，成交筛选独立展示，重复的“订单完成”行不再展示；“原因与订单”统一显示中文原因，已知原因码使用明确中文名称，未来未登记的英文原因码显示为“其他未登记原因”，不直接暴露英文。平仓成交按纸面账本的批次和先进先出配对口径显示“本笔收益”，仅计算该成交实际闭合的数量，属于未扣费用的已实现毛收益。顶部模型和动作类型筛选同时控制两边，两个纸面账户的库存与收益仍严格隔离。

页面顶部可切换到“模拟回看”：选择 SQLite 中已有的交易日，拖动时间轴或按 1×、10×、60×、300× 播放。播放跨过 11:30 时会直接跳到 13:00，不等待午休空档；时间轴拖入 11:30–13:00 时也会按拖动方向吸附到午休前后边界。每个回看时点都只采用该时点及以前的行情和纸面成交；盘口来自 `raw_ticks`，模型现金和库存按 `maker_paper_fills` 重建，订单按创建、成交和最终更新时间推导当时状态，合理价与趋势由做市分析器按时间顺序因果重放。回看期间停止实时轮询，切回“实时快照”后恢复。

顶部第三个“手动接管”栏目同屏提供两债的买入/卖出、委托张数、起始价和极限价。买入在外部买一严格领先时先撤旧单，再以外部买一加0.001元重挂；卖出按外部卖一减0.001元对称处理。盘口最优价等于本方当前价时不追自己的报价；价格只朝极限方向移动。继续领先若触及极限价，则撤销原单、停止任务并播放报警。每债可一键撤销，顶部可以二次确认后全部撤销。当前所有这些动作都由独立子项目`../半自动手动交易/`的干运行适配器执行，完整规格和测试边界见其README。

顶部“声音提醒”按钮点击一次即可开启，浏览器会记住该选择。提示音已针对系统音量约30%的日常使用环境适度增强：当前观察模型在任一债券出现挂单、撤单或订单完成时播放一次清晰的短促“叮”声；出现一笔或多笔新成交时播放更响、可明显区分的双音成交提示，并在同一轮刷新中优先于委托提示，避免重复响铃。首次加载只建立动作基线，不补播历史声音；切换模型或从模拟回看返回实时后也会重新建立基线，模拟回看本身始终静音。受浏览器自动播放规则限制，刷新或重新打开页面后若按钮显示“点此激活”，需要再点击一次恢复声音。

安全边界：服务端使用 SQLite 只读行情连接；15:30 后持续页面不再轮询 SQLite 或重建策略快照，手动接管也不允许新启动；页面审批和手动追价都不发送真实委托。只有手动动作审计会写入独立、本地忽略的JSONL运行文件。
