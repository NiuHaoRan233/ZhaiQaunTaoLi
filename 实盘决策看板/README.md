# 实盘决策看板

## 项目目标

建立独立的盘中决策工作台，以实时盘口为核心，直观展示每个模型的判断、信号和动作，为后续“模型提出建议、人工检查后决定是否放行”的实盘工作方式做准备。

本项目与策略规则文档分开维护。策略模型仍由现有做市引擎负责；本目录只管理看板产品、交互、审批流程及其实现。

## 长期产品定位

系统的最终目标是把行情数据、模型决策、账户状态、风险检查、委托执行和成交回报连接成一条自动运行链路。程序启动并通过启动前检查后，正常交易过程不要求人工逐笔批准；看板作为这条链路的控制面板，集中展示各模型和账户的运行状态，并提供启停及盘中风险控制入口。

控制面板需要明确区分不同强度的操作，不能把它们合并成一个含义模糊的“停止”按钮：

- 暂停模型决策：停止生成新建议，但不擅自处理既有挂单或持仓。
- 禁止新增风险：允许减仓和补回客户底仓，不再增加额外库存或方向暴露。
- 撤销活动委托：撤掉指定模型、账户或全局范围内尚未完成的订单。
- 紧急停止：阻断新委托并撤销活动委托；是否主动平仓必须由独立、明确且经过验证的规则决定。
- 盘中风控：监控库存、现金、亏损、行情数据新鲜度、账户连接、委托回报和模型异常，并按已配置规则降级或停止。

所有控制动作都必须具有明确作用域、二次确认、操作者、时间、触发原因和执行结果记录。看板显示“已停止”之前，必须以执行端和账户回报确认实际状态，不能只依据浏览器按钮状态。具体止损阈值、触发后只停新单还是撤单、是否以及如何平仓，当前仍属于待确认规则，不在看板层自行推断。

## 核心视图

- 以债券实时盘口为底图，分别叠加第一顺位1.1、1.37、1.43及其他执行分支的挂单。
- 明确显示每张模型订单的方向、价格、数量、建立时间、当前状态及第一顺位或排队信息。
- 实时显示挂单、撤单、改价、部分成交和完整成交，并解释动作原因。
- 为每个模型单独展示动态合理价与合理区、趋势、关键证据、库存、客户底仓缺口、当前信号、拟执行动作及不行动原因。
- 保持模型身份独立，不把不同模型的挂单、仓位、成交或收益合并。

## 人工放行流程

未来的目标流程为：模型生成可解释的订单建议，建议进入待检查状态，由用户批准、拒绝或修改。系统应同时保留模型原始建议和人工处理结果，便于区分模型判断与人工覆盖。

每次建议至少记录模型ID、产生时间、因果行情快照、方向、价格、数量、理由、有效期限、人工决定及决定时间。等待期间若盘口、合理区、库存、风险边界或原始信号发生实质变化，旧建议必须失效并重新生成，不得直接执行过期建议。

## 当前安全边界

当前阶段只实现可视化和模拟批准、拒绝闭环。继续保持行情只读和纸面执行，不导入或调用`xttrader`，不发送真实委托。任何真实交易连接都属于后续独立阶段，需要另行设计和安全验收。

## 待确认事项

- 盘口展示深度、刷新频率和每个模型的颜色标识。
- 多债券采用同屏、分页还是独立窗口。
- 人工批准时是否允许修改价格、数量和有效期。
- 建议超时及行情变化导致自动失效的具体条件。
- 盘中提醒方式以及收盘后的审批和执行复盘格式。

## 当前原型

已提供本地 Web 看板原型，直接读取父项目 `data/zhaiquant.sqlite3` 的实时纸面账本：

```powershell
.\start_dashboard.cmd
```

浏览器打开 `http://127.0.0.1:8765`。当前页面把 G三峡EB2 与 26江铜EB 同屏固定展示，不再依赖债券切换。每只债券分别显示最新价、紧凑的近一小时分时、动态合理区、放大的五档盘口、买卖价差和市场成交增量。市场成交从上到下按时间正序排列，最新一笔位于列表底部；列表刷新后默认定位到最新成交。成交方向沿用通达信式 `B` / `S` 简写（B红、S绿）；方向仍是本地推定，不是交易所 Level 2 主买主卖标志。

默认只观察一个模型，通过紧凑下拉框切换其他已登记模型；两只债券盘口只叠加当前模型的活动纸面挂单。下拉列表和展示状态以数据库中的模型指派与正式纸面账本为准，不在看板代码里另建一套“当前模型”真源。当前后台实时比较顺序为第一顺位1.37、第一顺位1.43、排队1.17；它们仍是未部署候选，生产基线仍为第一顺位1.1、排队1.0和Windfall 1.0。

挂单按真实价格顺位贴在对应买卖档右侧，用紧凑的 `B/S + 委托价 + 数量` 标注显示：例如买一137.000、改善一厘买单137.001时，`B 137.001`直接标在买一行；卖单同理。五档内部的插档价也归入对应档位，只有真正低于买五、高于卖五或越过正常被动报价范围的委托才单列为“盘口外（超出五档）”。下方动作流水合并展示当前模型在两只债券上的挂单、撤单、买卖成交及订单号，两个纸面账户的库存与收益仍严格隔离。

页面顶部可切换到“模拟回看”：选择 SQLite 中已有的交易日，拖动时间轴或按 1×、10×、60×、300× 播放。播放跨过 11:30 时会直接跳到 13:00，不等待午休空档；时间轴拖入 11:30–13:00 时也会按拖动方向吸附到午休前后边界。每个回看时点都只采用该时点及以前的行情和纸面成交；盘口来自 `raw_ticks`，模型现金和库存按 `maker_paper_fills` 重建，订单按创建、成交和最终更新时间推导当时状态，合理价与趋势由做市分析器按时间顺序因果重放。回看期间停止实时轮询，切回“实时快照”后恢复。

安全边界：服务端使用 SQLite 只读连接；15:30 后持续页面只返回最后缓存，不再轮询 SQLite 或重建策略快照；页面审批不写数据库、不导入 `xttrader`、不发送真实委托。
