# 半自动手动交易：比价追价与人工接管

这个子项目为全自动模拟盘之外的“人工判断、程序执行”路径做准备。用户决定债券、方向、数量、起始价和经济极限，程序负责维护价格优先、监控任务状态、在触及极限时撤销并报警。它是独立的人工接管分支，不改变现有第一顺位、排队或 Windfall 模型，也不共享它们的账户、委托、库存或收益。

## 当前安全边界

当前实现严格为纸面干运行：

- 行情只从 `data/zhaiquant.sqlite3` 的 `raw_ticks` 只读获取；
- `DryRunExecutionAdapter`只在内存中建立、撤销和查询干运行订单；
- 服务状态固定返回`broker_orders_enabled=false`，核心引擎拒绝非纸面适配器；
- 不连接交易接口，不向券商发送任何委托；
- 动作审计写到本地`runtime/manual_takeover_audit.jsonl`，整个`runtime/`目录已忽略，不提交 Git。

真实委托执行不属于当前仓库获准范围。未来只有在安全边界被明确修改并完成独立验收后，才可在另行批准的执行项目中实现真实适配器；不能在这里把干运行类悄悄替换成券商连接。

## 指令字段

每只债券同一时刻最多有一个活动或撤单未确认的接管任务：

| 字段 | 含义 |
|---|---|
| 债券代码 | 固定支持`132026.SH` G三峡EB2和`132024.SH` 26江铜EB |
| 方向 | 买入或卖出 |
| 委托张数 | 单位严格为“张”，必须是10张的整数倍；1手=10张 |
| 起始价格 | 启动时先按这个价格建立订单 |
| 极限价格 | 非执行边界：继续领先若将触及或越过该价，撤销当前订单、停止任务并报警 |
| 领先幅度 | 固定0.001元，即领先一厘 |

买入的极限价必须严格高于起始价；卖出的极限价必须严格低于起始价。

## 比价规则

买入任务：

1. 先按用户起始价挂出。
2. 只有外部买一严格高于当前委托价，才认定有人领先。
3. 先确认撤销旧订单，再按`外部买一 + 0.001`重挂剩余数量。
4. 所需新价大于或等于最高停止价时，不挂到该极限价；撤掉旧单、结束任务并报警。

卖出任务完全对称：外部卖一严格低于当前委托价时，先撤旧单，再按`外部卖一 - 0.001`重挂；所需新价小于或等于最低停止价时撤单停止。

盘口最优价等于本方当前委托价时，程序把它视为本方仍处于最优价，不继续改价。这一条用于防止真实适配阶段追着自己的盘口价格无限加价或降价。同价后来加入的竞争订单在价格优先上也排在本方之后，不需要响应。价格只朝极限方向单向移动；竞争者撤单后不会自动退回更便宜的旧价。

任何改价都必须遵循“撤单回报确认 → 计算剩余张数 → 新单提交”的顺序。部分成交后只重挂未成交张数。撤单确认失败时不得提交替代单，并把任务标为执行异常和“订单状态未确认”；该状态会阻止同债券启动新任务，但仍允许再次一键撤销。

## 看板操作

启动现有看板：

```powershell
Set-Location -LiteralPath .\实盘决策看板
.\start_dashboard.cmd
```

浏览器打开`http://127.0.0.1:8765`，切换到顶部“手动接管”。两只债券各自有方向、张数、起始价、极限价、启动和撤销控件；顶部“全部撤销”同时处理两债。启动操作会激活浏览器声音，触及极限、全部成交、行情失效或执行异常时播放三段报警音。

后台活动任务按300毫秒检查最新行情记录，但实际反应速度仍受 MiniQMT 采集写库频率约束；不能把300毫秒检查周期描述成300毫秒交易所行情或委托回报。工作日09:25（含）至15:30（不含）之外不轮询行情 SQLite，也不允许新启动；窗口结束会撤销仍活动的干运行订单。

本地接口为：

- `GET /api/manual/status`
- `POST /api/manual/start`
- `POST /api/manual/cancel`
- `POST /api/manual/cancel-all`

## 目录

| 路径 | 内容 |
|---|---|
| `manual_takeover/core.py` | 价格优先状态机、订单生命周期、数量和极限价校验 |
| `manual_takeover/runtime.py` | SQLite只读行情、干运行执行器、后台监控和JSONL审计 |
| `tests/` | 买卖对称、自身报价防追、部分成交、极限停止、撤改顺序与只读行情测试 |

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s 实盘决策看板\tests -p "test_*.py" -v
```

## 已知限制与真实适配前置条件

当前干运行订单不会出现在真实盘口，也不会凭 Level 1 行情虚构成交。真实阶段至少还需要经过以下独立验收：

- 账户、股东代码、市场和买卖权限的明确选择与启动前检查；
- 券商订单号、异步委托回报、部分成交、废单、撤单竞争成交和重连后的状态恢复；
- 用本方订单价和订单回报避免把自身买一/卖一误认成竞争者；
- 行情过期、委托回报过期、断线、重复请求和进程重启时的安全停机；
- 真实持仓、可用数量、现金、费用、涨跌停、价格笼子和单笔/当日风险上限；
- 所有启动、撤改、成交、人工覆盖和异常均有不可抵赖的账户回报审计；
- 沙盒或券商仿真环境端到端测试，以及小额度实盘的单独人工批准。

旧目录中的`之前的工作的一些内容/比价策略.rzrk`是高熵专有导出文件，不能作为普通源码直接审阅。本实现以用户本次确认的外部行为作为规格，并用上述测试锁定，不声称复用了旧文件内部代码。
