# 债券活跃度观察：会话输出约定

本目录继承仓库根目录的只读和本地数据边界。回答债券活跃度问题前，先读本文件及 `README.md`。以下是用户于 **2026-09-07** 明确要求长期记住的输出偏好，适用于聊天答复、扫描报告和补充名单。

## 每次名单都要保留双债参照与评分

1. 始终把 **132024.SH 江铜EB** 和 **132026.SH G三峡EB2** 放在名单最前列，两只均显示 **100分（人工确认参照）**。名称可采用当日 QMT 简称，身份以代码为准。
2. 即使用户追问“还有别的吗”“没别的了吗”，或要求展开非铁路债、其他类别，也必须在输出中保留这两只及其评分，不能因为上一条答复已经提过就省略。
3. **本次观察名单中的全部债券都要带上评分一起输出。** 每只至少列出代码、名称、综合评分，再配成交额、成交笔数、价差等依据；不能只列名称、金额或笔数而漏掉分数。
4. 两只参照之后，其他债券原则上按综合分降序排列。名单较长时可以在聊天中突出重点，但须保存并链接完整的带分名单，不能悄悄省略其余候选的评分。
5. 标明数据日期、截止时间和“近日”的统计窗口；区分今日活跃与前几日活跃、今天转弱。

## 评分必须有可核对的依据

- 沿用 `config.json` 与 `README.md` 规定的评分口径：成交额30%、成交笔数30%、日内成交价差30%、五分钟成交持续性10%，综合分取今日分与近5日分中较高者；两只人工参照100分，其他债最高99分。
- 对扩展候选，先核对数据口径、补齐评分输入并计算分数，再输出名单。不能为满足展示要求凭印象编分，也不能把缺失数据当作零分。
- 2026-09-07 的扩展核验发现，部分深市券的 tick `amount` 为零，但日线金额与 tick `transactionNum` 有数据；日线金额与 tick 金额也可能不一致。不能直接混用这两种金额来生成可比评分，更不能仅凭今天 tick 金额为零就断言近日不活跃。
- 若客观上仍无法取得可比数据，评分栏须明确写“待评分”并说明缺失或口径问题，不能无说明地留空、省略该券或伪造数值。100分参照身份与当日行情是否齐全应分别说明。

## 盘口价差比较优先使用全天平均

用户于 **2026-09-09** 要求：比较盘口价差及其占价格百分比时，优先使用全天平均，不用某一时刻的报价代表全天。此偏好也适用于本目录下的期权等扩展市场观察。

- 默认用有效连续交易时段的时间加权平均：逐帧计算 `(卖一－买一) / ((买一＋卖一)/2)`，再按盘口持续时间加权。明确这属于计算口径，不能把中位数或逐帧简单平均称为全天平均。
- 盘中尚未收盘时注明“当日至截止时间平均”；收盘后补齐完整连续交易时段。排除集合竞价和午休，列明数据覆盖与无效、陈旧报价的处理方法。
- 跨品种对比应使用可比窗口；例如ETF期权连续竞价止于14:57，两只EB若也截到14:57，须说明这是共同对比窗口，不是债券截至15:30的全交易日。
- 极宽报价可能抬高均值，可并列时间加权中位数及必要的分时解释，不能不说明就删除极端值。价差比例以期权权利金价格为分母时，不能冒充保证金收益率或已实现套利收益。
- 此处“盘口买卖价差”与既有活跃度评分中的“日内最高成交价减最低成交价”不同；展示口径调整不自动改变 `config.json` 的评分规则。

这些要求是活跃度观察的输出约定，不构成做市交易规则或纸面模型版本变更。
