# 债券活跃度观察

这是一套独立、只读的机构信用债观察流程，用来回答：今天或近日，哪些地产、城投、产业等交易所信用债相对活跃，值得再打开盘口人工查看。

它不属于做市模型，不生成交易信号，不调用`xttrader`，也不会发送委托。候选代码、名称、当日累计成交额和历史tick全部来自当前MiniQMT的只读`xtdata`接口，不使用新浪或其他第三方行情。

## 一键运行

双击`运行今日扫描.cmd`，或在项目根目录执行：

```powershell
.\债券活跃度观察\运行今日扫描.cmd
```

运行前需要先启动MiniQMT，并保持行情连接正常。程序从项目根目录的`config.toml`读取QMT端口。当前项目虚拟环境已具备所需依赖；若以后换机后提示缺少`xtquant`，执行一次：

```powershell
.\.venv\Scripts\python.exe -m pip install -r .\债券活跃度观察\requirements.txt
```

常用参数：

```powershell
# 每组显示前25只
.\债券活跃度观察\运行今日扫描.cmd --top 25

# QMT临时不可用时，用最近一次本地快照重新生成报告
.\债券活跃度观察\运行今日扫描.cmd --offline
```

运行后主要看：

- `reports/latest.md`：最新可读报告；
- `reports/*.csv`：最新筛选明细，可用Excel继续排序；
- `data/snapshots/*.csv`：每日快照，供后续比较近日活跃度。

Markdown报告先列全体信用债活跃榜，再单列“地产、城投线索专项”；即使这两类当天没有进入总榜前列，也能看到各自相对靠前的候选。

运行时生成的`data/`和`reports/`属于本地状态，已经由本目录的`.gitignore`排除。

## 筛选口径

候选结果以交易所信用债为主，排除其他可转债、可交换债和利率债。`132024.SH 26江铜EB`与`132026.SH G三峡EB2`是人工确认的100分交易价值参照，同时也是重要观察对象，因此固定显示在总榜最前列，不会再在计算标尺后从报告中排除。

报告会按债券简称给出“地产线索”“城投线索”或“其他信用债”。这只是初筛提示：QMT行情字段没有直接给出合格投资者准入结论，简称也不能完整证明发行人性质，因此选中某只债后，仍须在QMT终端逐券核验投资者适当性、账户权限、发行人、评级、期限和特殊条款。

程序先从QMT的“沪深债券”板块取得完整代码集合，再读取QMT全量实时快照；只有报告日期与QMT行情日期一致且QMT累计成交额大于0的信用债才进入候选。随后下载这些候选的QMT历史tick。活跃度的核心含义是“可交易价值”，统一以`132024.SH 26江铜EB`和`132026.SH G三峡EB2`为100分参照，并从四个维度衡量：

- 场内成交额占30%，直接使用QMT累计`amount`，衡量可容纳的交易容量；
- 场内成交笔数占30%，直接使用QMT累计`transactionNum`，衡量机会是否由多笔真实交易形成；
- 实际成交价差占30%，取QMT当日累计最高成交价减最低成交价，衡量可能存在的做T价格空间；
- 成交持续性占10%：一个“活跃时段”定义为累计成交额至少增加过一次的五分钟区间，避免把一笔大宗成交误认为持续活跃。

每个维度相对江铜、三峡中较低的有效值计算并在100%封顶，再按上述权重加总。其他债最高99分，只有两只人工确认参照固定100分。综合分取“今日交易价值分”和“近5日平均交易价值分”中较高者，兼顾今天或近日活跃；80分以上为“非常活跃”，60分以上为“较活跃”，40分以上为“相对活跃”。

因此，大额、多笔但日内价差很小的债不会再仅因成交持续而得到满分；它仍可能因为容量和成交频率较好进入“较活跃”观察区。成交额、笔数、价差、活跃时段、相对自身放量和连续成交都会写入明细，便于人工判断分数来自哪里。

这个标尺用于宽松地寻找值得进一步查看的债券，不代表流动性一定足以容纳某个下单量。报告只是观察名单；真正研究某只债时，仍需检查逐笔成交、盘口深度、价差、停牌状态和自身可执行容量。

## 日常流程

建议在交易日10:00以后、午后和收盘后各运行一次：

1. 打开`latest.md`，先看“非常活跃”“较活跃”和“相对活跃”，再看地产、城投等主体线索；
2. 对感兴趣的债券人工查看盘口与逐笔成交；
3. 不因单日异常放量直接加入策略；
4. 连续运行至少5个交易日后，再重点看“近5日平均活跃时段”，并结合成交额判断是一笔大单还是持续成交；
5. 若要把某只债纳入现有做市研究，另行完成数据覆盖、因果机会和执行口径审计。

## 铁路债做T研究实验

`research_railway_maker.py`会把指定日期的QMT历史Level 1 tick转换为项目原生因果回放输入，并在临时SQLite账户中原样运行生产基线第一顺位1.1和排队1.0。它还会做0.02、0.05和0.10元三档稳定走廊敏感性测试，只允许先买额外仓、后卖实际买到的数量，不卖客户底仓。

```powershell
.\.venv\Scripts\python.exe .\债券活跃度观察\research_railway_maker.py --date 2026-08-21
```

输出保存在本目录`reports/railway_maker_*.md/.csv`。这是只读研究实验，不会把铁路债加入实时做市矩阵，不会注册或部署新模型，也不会调用交易接口。敏感性结果未计手续费、外部抢位和盘口冲击，只能用于筛选值得继续逐笔审计的标的与价差范围。

在上述压力测试之后，独立研究候选`railway_priority_v0_1_candidate`使用
`railway_priority_v0_1.py`研究五分至一毛的小价差稳定走廊。它不复用可交换债的
0.20/0.50元阈值：过去30分钟高低成交价簇必须重复出现、前后半窗都到达两侧且
中心漂移有限，之后才在低侧按第一顺位假设挂买；未来实际成交多少就只买多少，
也只退出该笔新增仓，不卖1,000张客户底仓。

```powershell
.\.venv\Scripts\python.exe .\债券活跃度观察\railway_priority_v0_1.py --dates 2026-08-17 2026-08-18 2026-08-19 2026-08-20 2026-08-21
```

报告同时比较0.05、0.08和0.10元门槛，以及成交归属折减和每张往返0.01/0.02元
费用压力。输出为`reports/railway_priority_v0_1_*.md/.csv`。该模型ID只登记为
只读研究候选，未进入生产或实时纸面矩阵；Level 1成交方向、真实排队和交易权限
仍需逐笔审计。

## 维护配置

`config.json`可以调整：

- 报告显示数量；
- 近几日比较窗口；
- QMT债券板块名称和项目配置文件位置；
- 满分参照代码和四项交易价值评分权重。

代码格式为`代码.交易所`，例如`132026.SH`、`123112.SZ`。

## 已知边界

- QMT“沪深债券”板块会包含已到期代码、可转债和利率债；程序先以QMT当日累计成交额过滤，再按代码和简称排除不属于目标信用债的品种。
- 当日成交额直接使用QMT实时快照的累计`amount`；成交频率使用QMT历史tick累计`amount`的正向变化，不使用分钟K线金额，因为两种QMT口径在个别深市机构债上可能不一致。
- 历史tick下载由QMT行情权限决定；若参照债历史tick不可用，程序会明确报错，不会回退到第三方数据。
- 成交笔数使用QMT的累计`transactionNum`，成交价差使用QMT累计`high-low`；它们是场内行情统计，不等同于逐笔方向或可保证成交的盘口利润。
- 盘中当日成交额尚未走完整天，因此上午报告适合横向比较，不应与历史整日成交额直接作绝对结论。
- `--offline`只读取已有QMT快照，不会伪装成实时结果。
