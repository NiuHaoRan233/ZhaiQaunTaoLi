# 第一顺位 v1.29：足额利润可见买一回补

状态：已实现、旧固定现金口径九日双品种回放、机会审计、订单差异审计和当时156项全量测试通过；影子候选、未部署。账户容量修正后的当前结果见文末附记，生产第一顺位仍为`maker_priority_v1_1`。

## 因果缺口

客户底仓卖出是经济做空，应按正常交易逻辑尽量买回。v1.28仍可能在已经有足额利润和当前可见低侧时，把回补单长期压在更深旧目标：

- 江铜2026-08-14在09:54:08以136.995卖出1,000张客户底仓，父版本仍把回补压在135.911。09:56买一136.201显示至少1,000张，相对卖价已有约0.794元利润；09:59又出现136.011低侧，利润约0.984元。继续只等135.911已经把普通回补变成捡漏赌注。
- 三峡2026-08-10在09:32:13以135.498卖出1,000张，父版本旧回补为133.399。09:36可见买一134.301已提供约1.197元利润和完整一标准手容量，仍不应因为旧深价目标而放弃当前低侧。

该问题和收盘敞口无关，也不是要求主动吃卖一。修正只建立被动第一顺位买单，必须等待后续真实卖盘成交。

## 通用规则

`maker_priority_v1_29_candidate`以`maker_priority_v1_28_candidate`为父版本，新增：

```python
enable_profitable_visible_bid_base_replenishment=True
```

只有以下条件全部满足时，底仓回补单才改为当前买一改善一厘：

1. 第一顺位账户库存低于日初1,000张，确有客户底仓缺口；
2. 已登记的底仓卖出均价有效；
3. 卖出均价减当前买一至少达到既有`minimum_active_entry_edge=0.50`元；
4. 当前买一显示量至少1,000张；
5. 改善一厘后仍保留至少0.50元利润，不穿越卖一；
6. 数量不超过底仓缺口、标准1,000张、库存容量和现金容量。

订单登记为`profitable_visible_bid_base_replenish`，只作路径身份追踪。它不复用触发前或当前已经发生的成交；订单建立后仍须由后续市场卖盘真实触及才能成交。不发市价单，不主动吃卖一，不读取证券代码、日期、固定价格或收盘时间。

若该权限完成一次底仓恢复，随后300秒内又形成一笔新的中等、卖墙支持底仓空头，v1.26动态回补可以在状态转稳或转强且当前卖一已有约0.20元利润时正常恢复，不再要求当前被动买单必须比卖一低1元。该放松只传播给这条明确身份链；其他中等空头继续保留v1.26的1元异常贪低门槛。

## 否决的宽原型

初版曾全局取消v1.26中等空头的1元异常贪低距离。它虽然修复江铜目标窗，却使三峡8月4日、8月7日和江铜8月4日、8月10日退化，已经撤销，不登记为模型。正式v1.29只允许最近由本权限完成的底仓恢复在300秒内传播一次身份，其他路径保持父版本。

## 测试与结论

新增`test_priority_v129_replenishes_a_profitable_base_short_at_visible_bid`，覆盖：

- v1.28父版本旧行为不变；
- 0.50元利润加完整买一容量触发；
- 买一不足1,000张不触发；
- 利润不足0.50元不触发；
- 新订单是被动限价，不能复用已有成交；
- 300秒身份链允许后续中等空头正常止盈；
- 没有该身份时不全局放松v1.26门槛。

全量156项测试通过，`git diff --check`通过。v1.29两债使用完全相同模型和参数，九日两边分别改善且机会捕获增加，但仍没有后续未讲解完整交易日，不部署。后续重点验证0.50元边界、买一显示量撤单、订单被击穿后的继续下跌和300秒身份传播。
