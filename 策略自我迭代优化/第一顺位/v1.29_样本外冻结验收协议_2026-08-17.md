# 第一顺位 v1.29 样本外冻结验收协议

> 历史状态说明：本协议对应04:36建立的旧固定现金口径冻结。开盘前账户审计发现固定136,800元会把明确的额外1,000张买入能力截小，因此该冻结清单已被`v1.29_样本外冻结清单_账户容量修正版_2026-08-17.json`取代。旧文件保留用于解释哈希变化，不再作为当前样本外入口；当前协议见`v1.29_样本外冻结验收协议_账户容量修正版_2026-08-17.md`。

冻结时间：2026-08-17 04:36:32（Asia/Shanghai），早于当日开盘。

状态：`maker_priority_v1_29_candidate`继续作为未部署影子候选；生产第一顺位仍为`maker_priority_v1_1`。本协议不创建v1.30、不改变任何交易规则，只把看见新行情前的模型身份、代码状态和验收标准固定下来。

## 1. 为什么现在冻结

本地只读数据库中的双债行情仅覆盖2026-08-04至2026-08-14，这九日已经全部参与v1.23—v1.29的统一回放和风险审计。2026-08-17凌晨尚未开盘，因此当前不存在可以诚实称为样本外的新交易日。

继续在原九日调阈值会重新引入三峡过拟合。正确顺序是：先冻结v1.29，再让同一模型、同一参数面对2026-08-17或之后首个数据完整且未参与调参的交易日。

机器可读身份见`v1.29_样本外冻结清单_2026-08-17.json`。若其中任一源码SHA256或策略profile SHA256不一致，必须先解释代码差异；不得把改动后的结果登记成冻结v1.29的原始样本外表现。

## 2. 冻结账户与分支

- 两个品种：132026.SH G三峡EB2、132024.SH 26江铜EB。
- 两者必须使用同一个`maker_priority_v1_29_candidate`、同一组开关和参数，不得加入证券代码、日期或固定历史价格条件。
- 每个品种、每个独立交易日都从1,000张客户底仓开始，并有足够纸面资金再买1,000张，正常库存范围0—2,000张。
- 卖出日初客户底仓是经济做空，必须持续按当前市场证据管理回补；卖额外买入仓位是平多，二者不能共用低门槛权限。
- 不要求收盘前恢复1,000张，不读取收盘时间强平，不因终态敞口好看而追价。日终缺口或额外多头必须如实报告。
- queue和Windfall保持各自冻结分支，第一顺位验证不得改变它们的订单、成交、库存或模型ID。

## 3. 数据完整性门槛

一个日期只有同时满足以下条件，才可登记为双债样本外日：

1. MiniQMT数据库同时存在两债和600900.SH在正常交易时段的因果Level 1数据，开收盘覆盖及会话来源可解释。
2. 对交易时段异常长的无帧区逐段核查；确认缺帧的窗口只能标为数据边界，不能用盘后逐笔倒灌实时决策。
3. 通达信逐笔成交和逐笔委托若未完整采集，Level 1回放仍可登记，但机会捕获和现实执行只能标为“待逐笔补证”，不得宣称完整全天审计。
4. 重叠实时/回补帧继续按`code + market_ts_ms`去重并优先实时会话，不得重复累计成交量。

## 4. 固定比较对象与报告口径

同一个新日期必须用完全相同的去重行情分别重放：

- 生产基线：`maker_priority_v1_1`；
- 冻结候选：`maker_priority_v1_29_candidate`。

三峡和江铜分别报告，禁止用一边收益抵消另一边退化。至少输出：

1. 标准化订单、撤单、成交及每笔价格和数量差异；
2. 账面库存、相对日初客户底仓缺口、现金和日终实际敞口；
3. 盯市毛收益，并明确未扣费用和滑点；
4. 每一次客户底仓卖出的入场证据、合理价优势、低侧回补证据及是否存在上涨反证；
5. 客户底仓卖出后30秒、2分钟、10分钟的可见回补成本、最大不利上行和缺口持续时间；
6. v1.29足额利润买一回补触发后，买一是否撤退、被击穿或继续下跌，以及订单是否发生不利选择；
7. 300秒身份传播期间市场结构是否已经实质改变；
8. 若逐笔完整，机会底表双腿捕获、经济路径替换、容量限制和所有未捕获模式内候选。

收益只用于核对经济路径。若候选少赚来自正确拒绝低确定性做空，不能只凭收益判负；若候选多赚依赖未来信息、缺帧倒灌或不真实成交，也不能判正。

## 5. 保持、否决与新版本条件

- 保持v1.29：两个品种均没有新增逻辑错误、成交可执行、客户底仓风险符合用户逻辑；即使某日没有新增机会，也不为版本号增长改规则。
- 否决或继续影子：出现低确定性卖客户底仓、转强后冻结旧回补目标、买一显示容量不足却成交、库存/现金越界，或同一规则在两债表现出相反的逻辑后果。
- 建立新候选：只有新日暴露了可用用户语言解释、当时因果可见、两债可共用并有正反例边界的真实缺口。任何订单、成交、库存或执行假设变化必须登记为v1.30或更高版本，旧v1.29结果不可改写。
- 晋级生产：单个样本外日仍不自动授权部署，必须累计后续未讲解完整交易日并由用户确认。

## 6. 收盘后执行顺序

1. 只读检查数据库日期、两债/正股覆盖、会话重叠和缺帧。
2. 先核对冻结清单的源码与profile哈希；如有差异，保留差异说明并使用冻结代码快照，或明确把结果登记为另一代码状态。
3. 用只读源库和临时SQLite分别回放v1.1与v1.29，不写入真实运行库。
4. 有完整通达信逐笔时，再生成机会底表、现实成交/队列审计和路径join。
5. 先逐笔审计逻辑与风险，再查看汇总收益，最后决定保持v1.29、否决某项能力或注册下一候选。

标准只读入口为`scripts/audit_priority_sample_out.py`。它只允许生产v1.1和冻结v1.29，源数据库以只读模式打开，回放写入临时SQLite；提供冻结清单时会在回放前核对profile、审计工具自身和相关源码SHA256，并复核1,000张底仓、额外1,000张容量及模型ID。不一致即退出；旧校准日可以用于冒烟复核，但报告会明确`sample_out_eligible=false`，不得冒充样本外。

仅做Level 1回放示例：

```powershell
.\.venv\Scripts\python.exe scripts\audit_priority_sample_out.py `
  --config config.toml `
  --date 2026-08-17 `
  --code 132026.SH `
  --model maker_priority_v1_29_candidate `
  --freeze-manifest "策略自我迭代优化\第一顺位\v1.29_样本外冻结清单_2026-08-17.json" `
  --output tmp\v129_132026_2026-08-17_replay.json
```

同一日期须把`--code`分别换成两债，并把`--model`分别设为`maker_priority_v1_1`和`maker_priority_v1_29_candidate`。取得完整机会JSON后，再增加`--opportunities`和可选的`--diagnostics-output`生成机会与路径报告。

本协议的目的不是预先要求v1.29赚钱，而是确保它面对新行情时，评价标准不会随结果移动。
