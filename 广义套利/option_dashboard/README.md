# 商品期权盘口看板

2026-09-12 新增的独立只读行情工具。按用户的同花顺参考图组织品种导航、认购/认沽合约链、盘口分时和五档/成交明细。主图画买一、卖一及各自挂单量，不以末笔成交价代替挂单曲线。

## 启动与停止

1. 保持本机 MiniQMT 行情服务登录。
2. 双击上一级的 `启动期权盘口看板.cmd`，浏览器打开 <http://127.0.0.1:8766>。启动器检查已有服务，避免重复启动。
3. 关闭浏览器不会停止采集。需要停止时，双击 `停止期权盘口看板.cmd`；服务先取消本身的行情订阅并写完待保存队列。

启动器使用 PowerShell 7，Python 使用仓库已有 `.venv`，读取根目录 `config.toml` 的 `[qmt].port`（本次机器实际为58610，不能硬编码说明中的默认端口）。不修改配置。无需 npm、CDN 或互联网前端依赖。

前台诊断，在 `广义套利` 目录执行：

```powershell
..\.venv\Scripts\python.exe -X utf8 option_dashboard\server.py
..\.venv\Scripts\python.exe -X utf8 -m unittest discover -s option_dashboard -p test_*.py -v
```

前台 Ctrl+C 可以停止服务；`--port` 可改HTTP端口，但双击启动/停止入口固定使用8766。

## 使用方法

- 左侧选择交易所、品种；搜索支持中文品种名和完整/部分合约代码，跨全目录查找。
- 月份选择与主力月、次主力月、全部月按钮联动。主/次主力以**最新标的期货持仓量**排序、成交量破同序；没有期货持仓时明确回退至各月期权持仓合计。这是当前快照排名，不是历史时点排名。
- 下方认购/认沽链按月份和行权价配对；点击某一侧任意单元格切换主图。默认按两侧较大成交量降序；点击认购或认沽的成交量、买一价、卖一价等表头，按该侧对应数值排序，再点一次切换升降序。同一行两侧合约保持配对，缺失报价始终排在最后。下拉框还可选择行权价、持仓、价差率，并筛选双边有效报价。T形报价数字放大为17px、行权价20px，整体文字同步加大。
- 顶部“期权合约链”可展开链表；“盘口分时”回到图表。星号添加自选，自选保存在当前浏览器。
- 日期使用北京时间**自然日**，可选全天、日盘、夜盘/凌晨。9月11日的日盘和晚间夜盘可能属于不同交易日；9月12日凌晨应选9月12日。此版本不伪造交易所交易日映射。
- 滚轮缩放、拖动平移，悬停查看当时价格和数量，右侧五档同步到历史时点。离开主图恢复图末五档。点击成交明细定位到事件前后一分钟；右侧事件分页100条，全部事件均保留。
- 右上角显示所选自然日的**全天平均价差、全天平均价差比例**，始终使用该日全部已取得快照，不随日盘/夜盘筛选、缩放和悬停改变。价差=卖一−买一；比例=(卖一−买一)/买卖一中点×100%。两项分别按每条报价到下一条报价之间的持续时间加权（不是平均价差再除平均中点）。仅统计价格/数量均有效且未交叉的双边报价；锁盘计零价差。同毫秒、超过60秒的间隔、跨累计量重置的间隔不计权重，末条报价不向未来延长。旁边列出有效连续报价分钟数；无有效时长显示“—”。行情尚未完整时统计仅代表已取得的有效区间，不声称覆盖全天。导出JSON包含同口径的`dailySpread`统计。
- “自动刷新”每5秒更新当前品种链和接收状态；当主图选择当天时同步追加本地新行情。浏览器页面隐藏时停止页面轮询，后台接收记录继续。浏览器没有自动替换用户选定的历史日期。
- “重取历史”向QMT重新请求该合约所选自然日；“导出”保存全部规范化五档快照、量增事件和推断依据为JSON。

## 数据范围与边界

本机实测共64品种、23,252个商品期权合约，来自上期所SF、大商所DF、郑商所ZF、广期所GF。四个市场的全推订阅均成功，订阅回调已实测到达并写入SQLite；能源中心INE目录仍未返回。目录在启动/重连和每日日期变化后刷新，新合约自动进入已订阅市场的记录范围。不要称为全国无缺口覆盖。

**全目录与当前快照一次覆盖全部合约，服务运行时记录全市场回调；历史分时按用户选择的合约、自然日按需下载。** 不是已经下载23,252个合约所有历史日期。没有返回盘口的合约显示缺失，不生成演示曲线。QMT历史、接收快照是否完整仍受行情源授权、服务器记录和网络影响。

2026-09-12 23:37复核发现6,835个最新快照的QMT时间晚于本机当前时间，部分显示9月14日。这些原始时间保存并在页面“时间待核”中计数，合约链悬停显示原时间；它们不参与默认历史日期选择，不将未来快照放进当前分时。后一天启动时获取的前日静态收盘快照也不插入前一天的历史盘口。

合约链和顶部市场统计是**最新快照**，主图和右侧五档是**用户所选自然日**，两个范围在界面分别注明。QMT只返回买卖一时，其余档显示“—”，不从别的来源补造五档。

## B / S 的严格口径

每相邻快照的累计 `volume` 正增量是一条“成交量增事件”。每条事件都进入主图和明细，不降采样为分钟线；全日视图像素有限，密集事件可能重叠，可放大和翻页逐条看。

| 标记 | 因果判断 |
|---|---|
| B ↑ | 本次末笔成交价达到或超过此前有效卖一 |
| S ↓ | 本次末笔成交价达到或低于此前有效买一 |
| 灰色 ◆ | 价差内、此前报价缺档/锁盘/交叉、超过60秒、同毫秒/乱序或成交价无效 |

只使用**前一条**快照盘口，不用本次已变化的盘口和未来信息判断。买卖一有效要求价格和对应数量都大于0、买一严格小于卖一。首条输入、累计量回退、夜盘新交易周期首条不生成成交；夜盘跨午夜不误当新周期。没有交易所逐笔源时，不能把一次正增量当成一笔真实成交，也不能把末笔价格方向赋予增量中每笔交易。本版本没有报价内tick-rule猜测，证据不足保持中性。

图中买卖报价缺档就断线，间隔超过60秒或累计量重置也断线。每条原始接收记录保留接收时间、QMT时间和JSON；图表以市场时间稳定排序展示，同毫秒不同盘口保留。历史下载与接收记录重叠处仅去除相同规范化快照，不把休市后重新收到的旧收盘快照当作新的盘口变化。此排序仅服务只读观察，不能作为原有到达顺序纸面模型的重放输入。

## 实现与本地文件

- `market.py`：QMT目录、快照、市场全推、因果方向推断、历史补取与12个合约日内存缓存。
- `server.py`：仅监听127.0.0.1的HTTP服务；gzip传输；路径白名单；没有交易接口或委托功能。
- `static/`：无外部依赖的HTML/CSS/Canvas前端。
- `../data/option_dashboard/catalog.json`：本次全目录和元数据快照。
- `../data/option_dashboard/arrivals.sqlite3`：独立WAL数据库及其伴随文件。原始接收数据按到达ID保存，不读取或改动债券纸面账本。
- `../data/option_dashboard/<合约>_<日期>.json`：按需下载的自然日历史缓存。
- `../data/option_dashboard/server.*.log`、`server.pid`：服务日志和启动记录。
- `../reports/option_dashboard_coverage_20260912.json`：本次64品种/23,252合约链核对结果。

数据和日志均已由上一级`.gitignore`排除。全市场记录量会随交易活跃程度增长；应用没有静默删除历史的保留期限。SQLite备份应走SQLite在线backup API，或正常停止本工具后归档；不要直接复制运行中的WAL主文件。

## 验证

单元与HTTP测试覆盖前盘口因果性、B/S/中性、累计量重置、夜盘周期、午夜连续性、缺档、非有限值、重复回调、跨日静态快照排除、历史/实时同毫秒合并、主力排名、未来时间、未知合约和静态路径越界。

本次对64个品种逐一请求合约链并核对合约数合计23,252；用橡胶、玉米、棉花和碳酸锂实测四所历史请求，碳酸锂高成交样例超过2万条快照。浏览器实测月份/次主力、代码搜索、B筛选、图表缩放和合约链切换。周六休市时验证的是历史和订阅初始回调，开市后的持续吞吐仍需在实际行情下观察，界面持续展示回调写入数、丢失数和连接状态。
