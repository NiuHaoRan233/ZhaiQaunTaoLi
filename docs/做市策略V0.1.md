## 1. 目标和边界

V0.1把人工看盘中的两类机会转成可解释、可逐帧回放的规则模型：

1. `low_bid_reversion`：有效价格锚仍在时，预埋买单承接远低于价格锚的小额急售。
2. `sweep_tail`：某档卖单被真实主动成交吃掉大部分后，主动扫掉少量尾单，并在跳档后的价格附近卖出。
3. `deep_discount_sweep`：开盘先用昨日收盘价作初始合理价；当日已有真实成交后，若卖一比因果合理价低至少0.50元，主动吃最多1,000张。相邻低价至少再改善0.05元才视为新机会，避免把同一个三秒快照重复成交。

开盘尚未形成可靠的当日成交锚时，模型先用昨日收盘价维护底仓卖单；卖一比昨收高出足够空间时，第一顺位挂卖一减0.001元，排队口径加入当前卖一。真实交易开始后，如果最新买卖盘口的中点在窄区间连续停留至少15秒，且该连续区间内中点波动不超过0.15元，则把中位中点作为早盘次级合理价。形成可靠当日成交锚后，合理价再切换到成交量与时间加权锚。15秒和0.15元均为透明初值，等待更多早盘样本校准。

库存退出价不冻结买入时的历史价格锚。实时挂单每个快照按当前合理价、趋势、当前卖一和库存性质重新判断：额外仓具备可周转空间且当前卖一处于局部合理区时，第一顺位挂卖一减0.001元，排队口径加入当前卖一；卖一上移时跟随撤改，不在盘口外保留历史远价单。历史成本用于风险与复盘，不定义当前合理价。

## 统一决策框架

买入、卖出和回补共用同一组因果输入，不再为单个历史案例增加独立补丁：

1. 合理价：开盘先用昨收；实际成交开始后，持续稳定的买卖区间可形成早盘次级盘口锚；当日成交锚可靠后切换到最近成交量加权锚，大成交权重更高，旧成交随时间衰减。
2. 空间：0.50元以上的偏离本身可作为主要安全来源；0.20至0.50元的偏离必须同时看到至少5,000张的近端承托。
3. 盘口墙：买一附近0.20元内的五档合计量用于判断承托；卖一附近0.20元内的合计量用于判断供给墙。厚卖墙既支持在合理区快速退出，也可在接近吃完时转成扫尾买回信号。
4. 库存：每天从客户或老板提供、经济上必须最终补回但不要求当日收盘前归还的1,000张底仓和可买1,000张的现金开始，最大账面库存2,000张。账面库存从1,000张降到0张只表示没有裸卖，经济上形成了1,000张必须买回的客户底仓缺口；上涨会提高回补成本并造成做空亏损。控制台、回放和评估必须同时显示账面库存与相对日初底仓的经济缺口。高卖后的回补通常应保留安全空间；若合理价和趋势已可信地上移，则允许为了恢复正确库存接受小额回补亏损，不能用上一笔盈亏取代当前市场判断。
5. 报价：第一顺位改善一厘，排队口径加入当前档位。每个快照按合理价、趋势、盘口空间和库存目的重新定价；历史成本是风险信息，不生成历史远价单，也不是硬性的合理价锚。
6. 五档疏密：近端厚墙是承托或供给安全垫；相邻卖档大幅跳空则表示近端卖压稀疏和潜在上行空间。两种状态必须分开处理。

其中0.20至0.50元加厚承托默认只支持在买一被动排队，不足以主动扫卖一。主动深折价买入通常要求至少0.50元空间；只有已经确认的大单突破支撑等更强状态，才允许降低主动门槛。

### 客户底仓做空权限与回补风险

卖出有历史买入成本的额外仓属于平多退出；卖出日初客户底仓属于新建经济空头。两者必须使用独立的权限判断和风险报告，不能只因账面库存仍不低于0就视为同等安全。

客户底仓卖出必须满足高于普通额外仓退出的证据阈值，并同时证明：拟卖价相对当前合理区有充分优势；低侧回补区由当时已可见的真实成交、持续盘口或其他可执行证据支持；趋势或重复高低走廊足以承担做空；不存在可信的上涨、清档或供给稀疏反证。单独的`possible_fall`标签、约0.18—0.20元瞬时买卖价差、技术库存不为负，均不足以授权卖掉最后一份客户底仓。

在`possible_rise/rising`中，旧成交锚、旧突破支撑或昨收相对现价的表面价差不能单独证明当前高估。若盘中已经产生近期真实成交，且没有足量高低成交反复形成的明确低侧回补走廊，第一顺位候选须以最近5分钟真实成交参考重新估值：卖价相对该参考至少达到既有约0.30元底仓高卖边界，并且卖一附近0.20元内合计供给至少5,000张。任一项不足，只能处理额外仓，不得新建客户底仓空头。盘初尚无当日真实成交时不虚构盘中参考，继续由昨收跳空、实际盘口和父版本安全边界判断。

额外仓卖出使库存回到1,000张时，下一份同价卖出已经从平多变成做空，必须重新取得底仓权限。第一顺位候选在其后15秒内若仍处于同一0.015元价格簇且状态为`rising`，只有出现以下任一新证据才可继续卖客户底仓：至少1,000张、低于拟卖价约0.20元的近期真实卖出；严格重复高低走廊；拟卖价相对最近5分钟真实成交至少高0.50元；拟卖价离开原价格簇；或隔离窗口到期。不能把上一笔额外仓退出的安全性自动传播给客户底仓。

经济缺口形成后，每个快照都必须重新评估回补，而不是冻结最初低买目标。若合理价上移、主动买盘增强或上涨得到确认，应提高回补报价，必要时接受小亏止错；不能为了等待原价而长期保持全部底仓缺口。用户已确认需要提高底仓做空阈值，但固定数值、证据组合和是否允许一次卖光最后1,000张仍待校准，因此现有第一顺位1.2以后基于约0.18—0.20元下行走廊的候选权限不得据此晋级或推广，必须先完成客户底仓经济负债口径的跨标的复核。

“持续寻找回补”不等于“收盘前强制回补”。第一顺位与排队成交均在午休以外正常交易到15:30，15:30前继续按合理价、趋势、盘口和库存目的买入、卖出、回补和做T，不得在14:56:30或其他未经确认的时点统一停单。普通纸面策略没有尾盘强平或强制恢复1,000张库存的权限；临近收盘不降低门槛、不强行追价，收盘可以保留底仓缺口或额外多头，并按实际终态报告库存、现金、相对日初底仓缺口和盯市结果。每个独立历史交易日仍以用户默认的1,000张客户底仓和足够再买1,000张的纸面资金重新初始化，除非用户另行给出跨日账户状态。

普通账户的开盘输入必须显式包含`initial_inventory_bonds=1,000`和`additional_buying_capacity_bonds=1,000`，并校验`maximum_inventory_bonds=2,000`等于两者之和。标准第一顺位和排队账户以债券数量容量作为买入硬约束；`initial_cash_cny`只作为人民币派生记账，不得在债价高于旧136.8元时把合法1,000张买单截成984—999张。若实际合法成交所需现金超过旧纸面余额，账户把`cash`与`initial_cash`等额增加所需差额，使盯市收益不变并记录资金补足；库存仍不得超过2,000张。Windfall独立账户继续受自身2,000元固定信用额度约束，不继承普通账户资金补足。

普通账户运行摘要和只读回放必须显式输出`customer_base_short_bonds=max(0, initial_inventory-inventory)`与`extra_inventory_bonds=max(0, inventory-initial_inventory)`。前者是必须持续管理的客户底仓经济空头，不得因为账面库存非负而隐藏；后者是可按普通平多权限退出的额外仓。日终仍按实际数值报告，不触发强制成交。

### 跨品种统一模型约束

132026.SH与132024.SH的普通第一顺位分支必须使用相同模型ID、相同策略开关和相同参数，不得按证券代码分流交易逻辑。允许规则依据当前因果可见的相对价差、成交强度、波动和盘口深度自适应；禁止使用证券代码、品种名称或某一天的固定价格作为权限条件。

候选验收必须按品种分别完成逐机会、逐成交、库存与经济底仓缺口路径比较。总收益不得把一个品种的退化与另一个品种的增益相抵；候选只有在两边都不新增逻辑错误、都不牺牲已确认模式内机会，并对至少一边带来可解释改善时，才可继续进入影子验证。若某项改动只在一个品种有效，必须证明差异来自统一的因果市场特征，而不是品种身份或历史样本专用阈值。

跨品种统一模型还必须遵守逐债正股输入合同：`132026.SH -> 600900.SH`，`132024.SH -> 600362.SH`。模型ID、决策开关、参数和计算方法相同；证券映射只决定同一个`stock_return_5m`因果变量读取哪只真实正股，不得成为买卖权限条件。每个做市引擎只接收本债与其映射正股的行情，不能把全局`qmt.stock_code`广播给所有债券。

若某债在指定历史日期没有对应正股快照，回放必须报告`underlying_stock_code`、`underlying_stock_ticks=0`和`underlying_stock_data_available=false`，并按正股回报缺失处理，不得使用另一只正股、盘后标签、互联网日线或未来数据代替。该回放只能作为债券自身规则的受限校准证据。自动样本外门槛必须同时要求两只债及各自正股均具有完整早盘、尾盘和足量时间戳覆盖，否则返回等待状态且不运行任何一组模型回放。

### 趋势与库存联动

- 卖墙被真实主动成交连续吃掉、近端卖档清空并向上跳档、买一同步上移时，市场温度向上。合理区和已有库存的卖单应随新卖一上移。
- 如果大墙只剩符合扫尾条件的尾量且账户有库存容量，可主动扫尾；若账户已经持有足够库存，则不重复追买，直接把已有货挂到跳档后的新卖一附近。
- 卖一连续逐档下压、低价主动卖出增加、买一后退或承托减弱时，市场温度向下。合理区和卖出预期应同步下调，并降低追价意愿。
- 高位卖出后按最新买方区间维护回补和低接；每轮买卖都重新读取当前状态，不把上一轮的买价、卖价或盈亏当成下一轮固定目标。
- 单帧挂撤单不足以确认趋势。趋势判断必须结合连续盘口迁移、真实成交方向与速度，并允许随新证据减弱或反转。

### 下行盘口真空与近保本主动退出

新增仓成交后立即重新评估，不能因为入场逻辑正确就固定等待被动高卖。当账户库存高于1,000张底仓，并同时出现以下组合证据时，允许主动打当前买一卖出满足条件的新增仓：

1. 近30秒卖一连续下压至少约0.10元，且近期主动卖出量明显强于主动买入；
2. 买一到买二存在至少约0.10元断档，买二与买三的合计承托不超过约3倍标准下单量，买三到买四又存在至少约0.20元断档；
3. 当前买一仍有可见承接量，且相对该新增仓成本的损失不超过约0.015元，属于近乎保本的退出窗口；
4. 只卖高于底仓的新增批次，成交数量不超过当前买一显示量，不动期初底仓，也不把高卖后待回补的库存缺口误判成多头风险。

该动作标记为`active_downside_risk_exit`。它的目标是抢在关键买单撤走、价格向下一档跳空前恢复安全库存，不要求每一轮被动挂单都先成交。30秒、0.10/0.20/0.015元和3倍下单量都是透明初值，需要按后续人工复盘校准。

如果主动风险退出未触发，但卖一随后下压到仍比新增仓成本高至少约0.10元的位置，则把新增仓贴当前卖一退出。普通额外仓的被动周转不再硬性等待0.20元利润；固定利润门槛不能覆盖新的合理价、下降趋势和第二次可成交机会。

### 超级捡漏独立账户

`super_windfall`是与普通做T账户隔离的纸面策略：

1. 使用独立虚拟现金额度和最多10张（一手）库存，普通账户满仓或现金耗尽不阻止它挂单；
2. 取近10分钟实际成交参考与当前因果合理价中较保守的一项作为基准；
3. 当五档相邻买价出现至少1.00元断档，断档下方买价又比基准低至少1.50元时，在该异常深档改善一厘预埋10张买单；如果异常深档已经成为买一，也可用最新价/卖一与合理价确认同一机会；
4. 同一额度只保留一张异常价订单；只允许上移到后来出现的、更高但仍满足1.50元折价的新异常深档，不随普通买一逐档追高，也不计入普通账户库存、现金或收益；
5. 当前版本只定义发现与买入，成交后的退出规则标记为待人工补充。

本策略仍然只写本地模拟订单，不调用交易接口。1.00元断档、1.50元折价、10分钟参考和10张额度均为首版透明参数。

### 震荡段动态双边报价

当可靠成交锚和持续盘口锚暂时失效，但当日已经有真实成交、当前买卖价差不超过约0.80元时，允许暂用当前买卖中点作为低置信度工作合理价，避免午后异常跳价后错误退回昨收。该中点只指导被动做T和库存退出，不能单独触发主动深折价扫货。

新增仓卖出满足以下任一安全来源即可贴当前卖一：

1. 当前卖价比该批次成本至少高约0.10元；
2. 当前卖价比因果工作合理价至少高约0.30元，即使相对历史成本亏损也允许恢复安全库存。

期初底仓不使用第二条自动跟随孤立卖一。卖一附近供给稀疏、下一卖档大幅跳空时，底仓卖单应更保守；已有新增仓则仍可利用高于合理价的退出窗口。

新增仓的主动风险退出增加`fragile_top_bid`分支：买一显示量不超过约1倍标准下单量、买一到买二断档至少约0.50元、当前买一相对新增仓成本损失不超过0.015元时，立即卖出不超过买一显示量的新增仓。该条件不要求同时出现30秒卖一下压，因为风险来自最后一层可退出买单即将消失。

五档内若约0.075元的买价簇合计达到至少50倍标准下单量，则在控制台标记为强承托区。强承托只是低接安全垫，仍需合理价折价和库存容量；不能因为看见大墙就在合理价附近追买。

趋势输出采用五档离散状态：`stable`、`possible_rise`、`rising`、`possible_fall`、`falling`。V0.1先以透明评分生成诊断状态：近期主动买卖量不平衡、买卖中点迁移、卖一连续下压、已确认突破支撑和上方卖档断层分别形成可见证据。状态及每条证据必须在控制台展示，供人工逐日校准；在积累足够纠错样本前，诊断状态不单独扩大实盘权限，也不改变纸面只读边界。

稳定震荡是独立的正向做市模式，不是没有信号时的兜底标签。当前透明执行规则增加：

1. 近端买卖价差收窄到不超过约0.02元，且新增仓可以直接卖给买一获得至少约0.10元价差时，主动卖出新增仓完成快速周转；不处理期初底仓；
2. 近价厚买墙继续作为被动买入安全来源。约0.20—0.50元折价可以由至少5倍下单量的近端承托补足安全性；该承托在决策时必须仍然可见，确认撤单或消失后不再算成交后的即时退出通道，原买单应重新评估或撤掉；候选价逐渐远离厚墙时不继续追随小单抬价；
3. 约0.075元价格簇内超过50倍下单量的异常强买墙记忆600秒。非确认上涨状态下，普通买价最多高于该承托区约0.30元，避免强承托跌出五档后又跟随小单追到合理价附近；历史记忆只用于限制追价，不能把已经撤走的墙继续当作当前承托安全来源；真实卖档清空并跳档后的确认上涨在15秒迟滞窗口内可解除该限制；
4. `possible_rise`中若买卖中点在1分钟内快速上移至少约0.15元，但没有刚发生的真实清档上涨，普通被动买入需要至少约0.50元公允折价。上一笔高卖产生的账面回补利润不能绕过这一条件；
5. 只有主动买入成交在上一卖一附近发生、随后卖一至少跳升约0.15元，才把它记录为“真实清档上涨”，并给予约15秒确认状态迟滞。单纯在低位出现一笔被推断为主动买入、卖一并未清空，不算确认上涨；
6. 同时持有底仓和一份新增仓时，先只挂新增仓，不能把底仓以同价同时暴露，避免一笔较大成交在模型来不及重估时把两份库存一起卖掉。新增仓成交后，再用新盘口、合理价和趋势重新判断底仓是否值得高卖；底仓仍按专门的高卖安全条件管理。

5. 明确提示这是因果、可纠错的纸面模型判断，不是真实委托建议。

合理价与趋势判断只使用当前及过去数据。控制台读取SQLite并重建思考快照，不写交易表，不连接交易接口。

当前版本只读取本地SQLite行情，不连接交易接口，不发送委托。它首先用于验证“程序是否按照人工逻辑看盘”，不是已经完成参数校准的最终盈利模型。

## 独立机会审计工作流

策略迭代不得只围绕当前模型已经发出的信号复盘。每日先从完整逐笔成交和逐笔委托独立生成`market_opportunity`清单，再用机会发生前及当时的因果信息检查当前模型能否识别和执行：

1. 逐笔成交`B`按主动向上吃卖盘处理，`S`按主动向下砸买盘处理；通达信真实逐笔方向用于校准MiniQMT Level 1的`inferred_side`。
2. 第一层穷举所有有时间先后的异向成交正价差：`S低→B高`为先买后卖，`B高→S低`为卖出已有底仓后低价回补。严格正价差即保留，不设最低0.20元、不要求成交簇、不要求最低手数、不设回看窗口，也不读取模型信号。
3. 原始理论配对完整落盘。面向人工的报告另按相邻主动方向成交段压缩成局部往返，展示该段最早完成、最大价差、最小正价差、可匹配容量和嵌套配对数；压缩只解决重复阅读，不能删除或重新定义底层配对。
4. 理论配对和局部往返都不能直接相加为交易次数或利润，因为同一成交可能被多个嵌套配对复用。第二层必须沿一条不重复的库存路径核算容量、现金、手续费和成交顺序。
5. 模型是否已有仓位、现金、合理价证据和可成交位置只在第二阶段判断，不能反过来决定第一层是否存在机会。未来价格恢复、最大有利变化和持续时间只作为事后结果标签，不得成为当时决策输入；可执行性回放严格只读取机会时点及以前的数据。
6. 每个局部往返分别报告第一顺位和排队口径，并分类为`captured`、`missed_actionable`、`wrong_action`或`hindsight_or_unexecutable`；未精确匹配模型成交只表示“待因果审计”，不能直接叫漏做，排队口径还必须验证前方队列的真实消耗。
7. 只有可统一解释、在多个正例和反例中成立的`missed_actionable`才允许形成规则候选。任何会改变交易路径的候选都登记新模型版本并保留父版本，不在现有版本上原地改写。

这套工作流是评估和版本晋级纪律，本身不改变`maker_priority_v1_1`、`maker_queue_v1_0`或`maker_windfall_v1_0`的当前交易行为，因此本次文档补充不产生新的模型版本。

## 2. 数据口径

- `raw_ticks`：MiniQMT Level 1五档快照。
- `tick_changes`：由累计成交量和盘口变化本地推导。
- 债券盘口数量在MiniQMT中是手，模型按1手等于10张转换。
- `inferred_side`只是一级行情下的主动方向估计，不是交易所Level 2标志。
- 当前历史快照通常约3秒一帧，无法知道3秒内精确的委托先后顺序。

## 3. 价格锚

模型维护最近一段时间的成交证据，而不是把最新成交价直接当作合理价。

成交证据按以下因素加权：

- 成交数量；
- 距离当前时间的远近，默认10分钟半衰期；
- 主动买入或主动卖出方向；
- 相近价格是否形成成交簇；
- 正股最近5分钟是否明显下跌。

在强成交锚尚未建立的早盘，模型同时维护因果盘口证据：判断当前快照时严格只使用此前快照，取最新连续稳定区间内的买卖中点中位数。当前价格不能一边改变中枢、一边证明自己不再便宜或昂贵。瞬时跳价不能单独改变中枢；此前必须已经出现真实交易，并达到持续时间与稳定度要求。该盘口锚的优先级高于昨收、低于可靠的大成交锚。它可以指导被动买卖、撤改和额外仓退出，但宽价差中点不能单独触发主动吃卖一；主动买仍需昨收极端偏离、可靠成交锚或已确认的突破支撑。

主动买入成交簇用于建立：

- `support_price`：强成交簇中的价格下沿；
- `exit_price`：强成交簇中的价格上沿；
- `band_midpoint`：两者中点；
- `reference_price`：加入近期低价卖出压力后的参考合理价；
- `confidence`：成交量、买卖方向强弱和正股稳定性形成的置信度。

新的少量低价卖出会下调`reference_price`和置信度，但不会立即覆盖此前大量主动买入形成的锚。低价卖出持续放量后，旧锚会逐步失效。

## 4. 低价接砸

V0.1的候选条件是：

- 已有有效主动买入成交锚；
- 锚置信度不低于0.45；
- 当前买一低于参考合理价至少0.20元；
- 当前盘口有效且正股没有触发严重降权。
- 旧研究初值曾把新机会限制在09:30至14:56:30，2026-08-20经用户确认这是未经授权的程序机制，现已废止。正式规则为午休不触发、其余时间正常交易到15:30；临近收盘既不提前停单，也不降低条件或机械平仓。

每个候选同时记录：

- 加入当前买一时的显示排队量；
- 改善一厘、成为新买一的报价；
- 到支撑锚、参考价和上沿退出价的三档目标；
- 理论价差和理论毛收益；
- 未来10分钟内不同成交假设的验证结果和最大不利价格。

候选按5分钱价格带和60秒冷却去重，避免同一个盘口状态每3秒重复报告。

## 5. 大单扫尾

默认触发条件：

- 原卖档至少4,000张；
- 盘口减少必须由累计成交量确认，不能只依据撤单；
- 真实成交至少吃掉原卖档80%；
- 剩余尾单不超过2,000张；
- 尾单之后的下一卖价至少高0.15元。

历史Level 1只能证明该机会在当前快照中存在，不能保证程序能在下一个三秒快照前完成真实下单。因此扫尾结果会明确标记为主动扫单假设。

## 6. 四种被动入场结果

低价接砸候选同时给出四种结果：

- `optimistic`：成交价触及委托价即认为成交；
- `improved_priority`：假设改善一厘成为新买一，但保留一级行情时序不确定标记；
- `queue`：同价及更差价格的累计主动卖出量超过显示排队量加自身数量后成交；
- `conservative`：成交价穿过委托价至少一厘后才确认成交。

这四种口径是执行区间，不允许只展示乐观结果。

### 11.1 v1.21候选

`maker_priority_v1_21_candidate`以`maker_priority_v1_20_candidate`为父版本。在市场评估为`possible_rise`时，若当前帧满足以下条件，可把该帧登记为第一顺位专用的确认上涨事件：

1. `inferred_side == "buy"`；
2. `trade_bonds >= order_quantity_bonds`；

4. 当前最后成交价在合理容差内触及或高于上一卖一；

### 11.2 v1.22候选

### 11.6 v1.26中等优势底仓动态回补候选

`maker_priority_v1_26_candidate`以`maker_priority_v1_25_candidate`为父版本，只适用第一顺位。底仓卖单成交前必须记录其因果授权身份；只有以下全部条件成立，才标记为`medium_wall_supported_base_short`：

1. 卖价相对当前因果工作合理价的优势加合理容差后达到`minimum_base_high_sell_edge`，现值约0.30元；
2. 该优势严格小于`minimum_active_entry_edge`，现值0.50元，因而不属于深度高估；
3. 当前卖一附近0.20元内供给达到`wall_threshold_bonds`，现值5,000张；
4. 没有`repeated_turn_replenishment_price`，即不属于已确认重复高低走廊；
5. v1.24近期真实成交复核、v1.25平多后同簇隔离和父版本全部入场条件已经通过。

账户按底仓缺口数量和值追踪该身份。部分回补时按当前缺口组成同比例减少；完整恢复底仓时清零。若当前缺口混有其他授权来源，候选不主动覆盖，避免把深度高估或重复走廊的回补计划混入中等风险管理。

盘中主动回补必须同时满足：

```text
fill_mode == "priority"
and state in {"stable", "possible_rise", "rising"}
and inventory < initial_inventory
and all_outstanding_base_deficit_is_medium_wall_supported
and buy_order.kind == "inventory_replenish"
and average_base_sale_price - ask1 >= minimum_entry_edge       # 约0.20元
and ask1 - old_replenishment_limit >= minimum_windfall_book_gap # 1.00元
and ask1_bonds > 0
```

成交使用当前`ask1`限价，数量取底仓缺口、该身份数量、标准1,000张、卖一显示量、库存容量和可用现金的最小值；先以`dynamic_medium_base_short_replenishment`撤掉旧买单，再以`active_medium_base_short_replenishment`记录纸面成交。不得发市价单，不得超过卖一显示量，不作用于queue或Windfall。

### 11.7 v1.27确认上涨近乎平价底仓止错候选

`maker_priority_v1_27_candidate`以`maker_priority_v1_26_candidate`为父版本，只适用第一顺位。它不改变底仓高卖入场、额外仓退出、queue或Windfall，只处理底仓卖出后的快速因果反证。

主动回补必须同时满足：

```text

and state == "rising"
and inventory < initial_inventory
and replenishment_quantity > 0
and 0 < now - last_base_short_sale_time <= 30 seconds
and inferred_side == "buy"
and trade_bonds >= order_quantity_bonds                  # 至少1,000张
```
