# 做市模型版本记录

更新日期：2026-08-21

本文件是做市模型版本的唯一登记表。`主观做市策略手册.md`保存用户逻辑与案例，`做市策略V0.1.md`保存可实现规则；本文件回答“某个账户在某一天究竟运行哪个模型”。

## 编号规则

模型标识采用`maker_<执行分支>_v<主版本>_<次版本>`：

- 主版本变化：目标、库存定义、成交假设或核心状态框架发生不兼容变化。
- 次版本变化：在同一框架内新增、删除或改变会影响交易路径的规则。
- 纯文字、看板排版或不改变决策结果的修正不升级模型版本，但仍应写入项目变更记录。
- 已登记版本不可原地改写。候选改动使用新的候选版本，完成验收后才能标记为当前版本。

数据库中历史兼容的`strategy_id`可以继续保留，但每个交易日必须另行记录`model_id`和版本；模拟订单元数据也必须携带`model_id`，避免仅凭旧策略名猜测逻辑。

## 排队模型候选版本的自我迭代流程

系统可以自动寻找排队规律，但只能生成候选版本，不能自动替换当前版本：

1. 逐个历史挂单构建因果样本，只使用挂单当时可见的盘口、成交、合理价、趋势、库存和队列位置。
2. 标签至少包括：规定时间内是否成交、成交前方队列消耗量、等待时间、撤单后是否很快成交、成交后30秒/2分钟/10分钟的不利与有利变化。
3. 首先学习“保持、撤单、改价、主动成交、放弃”五类动作的条件概率和期望值；价格方向模型不能替代真实队列消耗模型。
4. 按交易日滚动验证：训练日在前，验证日在后；人工讲解过并参与规则形成的日期单列为校准集，不能冒充样本外。
5. 候选版本必须同时优于当前基线的风险调整收益、收盘库存、最大库存偏离和成交真实性；不能只优化单日利润或成交数。
6. 候选版本先进入独立的实时纸面账户，与当前排队1.0并行至少20个交易日；账户、委托、撤单和成交必须持久化。达到预先登记的晋级标准后由用户确认，才能成为新的当前版本。
7. 每次晋级登记父版本、数据切分、参数、指标和失败案例；表现退化时回退到已登记版本，不在原版本上偷偷改参数。
