# 每日债券做市交易 PDF 制作规范

最后更新：2026-08-24

本规范是 `output/pdf/` 下每日债券做市纸面交易报告的持久化制作依据。聊天记录、临时脚本和制作者对旧版的视觉印象都不能替代本文件。以后用户提出“制作今天的 PDF”“用某模型交割单制作”或要求修订当日报告时，先读本规范，再生成或覆盖成品。

## 1. 适用范围与标准成品

- 标准报告名称为“债券做市策略交易报告 - 损益拆分”，包含一页总览和按时间排序的完整成交流水。
- 当前批准的视觉基准是 `output/pdf/2026-08-21_债券做市策略交易报告_损益拆分.pdf`。后续批准的新成品可以接替它作为最近基准，但不得仅凭肉眼重新猜字体、字号或列宽。
- 2026-08-24 首次生成时曾误用等线字体；等线版不是字体规范来源。当天修订版及以后报告必须回到本文件规定的微软雅黑和 Arial 体系。
- 报告只描述纸面账户，不代表生产晋级、实盘部署或收益承诺。模型状态文字必须与 `docs/做市模型版本记录.md` 一致；进入实时比较矩阵不等于生产部署。

## 2. 输入与模型选择

1. 日期按 `Asia/Shanghai` 解释。“今天”使用当前上海日期；历史日期必须使用用户明确指定的日期。
2. 模型必须使用用户明确指定的模型，不得自动替换成当前实时矩阵中的其他模型。例：用户说“45模型”，应解析为第一顺位1.45，内部 ID 为 `maker_priority_v1_45`。
3. 对每只债券，从 `maker_paper_model_assignments` 按 `market_date + bond_code + model_id` 找到独立 `strategy_id`，再读取对应账户、订单和成交。不得把两个模型或两个账户的成交、现金、库存、损益混合。
4. 标准双债顺序固定为：
   - `132026.SH`：对外名称 `G三峡EB2`，流水简称“三峡”；
   - `132024.SH`：对外名称 `26江铜EB`，流水简称“江铜”。
5. 正式数据源为 `data/zhaiquant.sqlite3`。使用 SQLite 只读 URI 打开，使查询能够正确读取 WAL；不得为了制表直接复制正在运行的 WAL 数据库，也不得写入数据库。
6. 日报通常在 15:30 后制作。若用户明确要求盘中版本，必须在标题或摘要中写明截至时间，不得把盘中快照写成收盘日报。

## 3. 数量与损益口径

- 数量单位始终为“张”；1手等于10张。表格的“手数”必须由 `quantity / 10` 计算，不得把1,000张写成1手。
- 成交流水按 `market_ts_ms, id` 升序排列，同一秒的拆分成交不得合并或重排。
- 单笔成交金额为 `price * quantity`；双边成交额为所有买卖成交金额之和。
- 买入张数只汇总 `side='buy'`，卖出张数只汇总 `side='sell'`。
- 交易损益使用：

  `期末现金 - 期初现金 + (期末库存 - 期初库存) * 当日收盘价`

- 持仓损益使用：

  `期初客户底仓 * (当日收盘价 - 昨日收盘价)`

- 总损益使用：

  `交易损益 + 持仓损益`

- 当期末库存等于期初底仓时，应同时校验上述交易损益与账户保存的 `trading_pnl` 一致。
- 客户底仓缺口为 `max(0, 期初库存 - 期末库存)`；额外仓为 `max(0, 期末库存 - 期初库存)`。
- 未配平的当日交易仓位统一按15:30收盘价虚拟买回或卖出，只用于报告损益口径，不向数据库写入虚拟成交。
- 收盘价、昨收和行情覆盖时间从对应债券当日 `raw_ticks` 读取。封面按三峡、江铜顺序显示各自的首末行情时间。

## 4. 固定字体规范

### 4.1 必须使用的字体

- 中文正文：Microsoft YaHei，文件 `C:\Windows\Fonts\msyh.ttc`；ReportLab 字体名固定为 `MSYH`。
- 中文粗体：Microsoft YaHei Bold，文件 `C:\Windows\Fonts\msyhbd.ttc`；ReportLab 字体名固定为 `MSYH-Bold`。
- 英文、日期、代码、时间和所有数字：Arial，文件 `C:\Windows\Fonts\arial.ttf`；ReportLab 字体名固定为 `Arial`。
- 英文、日期、代码、时间和数字的粗体：Arial Bold，文件 `C:\Windows\Fonts\arialbd.ttf`；ReportLab 字体名固定为 `Arial-Bold`。

ReportLab 注册应使用以下等价写法；若当前 ReportLab 版本要求 TTC 子字体索引，则显式增加 `subfontIndex=0`：

```python
pdfmetrics.registerFont(TTFont("MSYH", r"C:\Windows\Fonts\msyh.ttc"))
pdfmetrics.registerFont(TTFont("MSYH-Bold", r"C:\Windows\Fonts\msyhbd.ttc"))
pdfmetrics.registerFont(TTFont("Arial", r"C:\Windows\Fonts\arial.ttf"))
pdfmetrics.registerFont(TTFont("Arial-Bold", r"C:\Windows\Fonts\arialbd.ttf"))
```

### 4.2 禁止的替代行为

- 不得以等线、宋体、黑体、Helvetica、系统默认字体或临时找到的其他中文字体代替微软雅黑。
- 不得让中文与数字全部共用一种中文字体；数字、金额、日期、时间、证券代码和页码必须使用 Arial 系列。
- 不得只看渲染截图判断字体相似。交付前必须用 `pdffonts` 检查实际嵌入字体。
- 合格成品的字体清单必须包含 Microsoft YaHei、Microsoft YaHei Bold、Arial、Arial Bold 的子集，不得出现 DengXian。

## 5. 固定页面与视觉规范

- 页面尺寸：A4 横向，约 `841.89 × 595.276 pt`，不旋转。
- 页边距：左右42pt；页脚分隔线位于约29pt；页码使用两位数格式，如 `01 / 03`。
- 主色固定为深蓝、青色、蓝色、琥珀色；买入使用青色，卖出使用红色。沿用批准基准的色值：
  - 深蓝 `#102F46`，辅助深蓝 `#173F5D`；
  - 青色 `#17A2A0`，深青 `#087F7E`；
  - 蓝色 `#2F75A8`；
  - 琥珀色 `#F1B84B`，深琥珀 `#B97800`；
  - 正文 `#152333`，次级文字 `#64798B`，页面底色 `#F3F7FA`。

### 5.1 总览页

- 顶部深蓝标题区高度约205pt，左上显示 `YYYY.MM.DD | DAILY TRADING REPORT`，主标题为“债券做市策略”，副标题为“X月X日交易报告”。
- 第一排固定四张指标卡：总损益、交易损益、持仓损益、双边成交额。
- 第二部分固定两张标的卡，左侧三峡、右侧江铜；每张显示总损益、成交笔数、双边成交额、交易损益、持仓损益、收盘、昨收、日终库存、底仓缺口和额外仓。
- 底部“今日摘要”必须写明总损益拆分、未配平仓位的15:30虚拟平仓口径、模型名称/内部ID/部署状态和两债行情覆盖时间。
- 所有正负号、千分位和两位小数必须使用 Arial；价格保留三位小数。

### 5.2 成交流水页

- 每页最多25笔；总页数为 `1 + ceil(成交笔数 / 25)`。
- 页眉左侧为“债券做市策略 / YYYY.MM.DD”，右侧为内部模型ID。
- 列顺序固定为：时间、债券、方向、价格、数量（张）、手数、成交金额（元）、成交说明、成交后持仓。
- 基准列宽依次为：`72, 70, 52, 68, 76, 52, 102, 140, 84 pt`；表头高22pt，行高约16.6pt。
- 买入方向使用青色粗体，卖出方向使用红色粗体；其余数字使用 Arial，成交说明使用微软雅黑。
- 成交原因优先使用稳定中文映射；遇到新原因时先在实现中增加明确映射，不得把内部英文原因直接留在最终 PDF。

## 6. 文件名与元数据

- 标准文件名：`YYYY-MM-DD_债券做市策略交易报告_损益拆分.pdf`。
- 同一天的修订直接覆盖该稳定文件名，除非用户明确要求保留“初稿/修订版”。不得无故生成多个“最终版/定稿版/更新版”。
- PDF Title：`YYYY-MM-DD 债券做市策略交易报告 - 损益拆分`。
- PDF Subject：`<model_id> 纸面交易报告`。
- Author：`Codex`。
- 成品只写入 `output/pdf/`，渲染 PNG、提取文本和临时生成器只放在 `tmp/pdfs/`。

## 7. 标准制作流程

1. 阅读根 `AGENTS.md`、本规范和当前 PDF skill；普通制表不属于策略讨论，不需要启动 maker strategy session，除非用户同时要求评判或修改策略。
2. 确认上海日期、用户指定的对外模型名称及内部 `model_id`。在数据库中确认两只债券各有且只有一个对应账户。
3. 只读查询账户、成交和收盘行情，先打印或核对两债成交笔数、买卖张数、期末库存、交易损益、持仓损益、总损益和双边成交额。
4. 打开最近批准的基准 PDF，使用 `pdfinfo`、`pdffonts` 和页面渲染确认页面尺寸、字体和布局。不得从零发明另一套视觉设计。
5. 在第一次创建或覆盖 PDF 前，按 PDF skill 要求成功登记一次 artifact operation；新文件用 `create`，覆盖既有文件用 `edit`，预期输出数量为1、格式为 PDF。
6. 使用 ReportLab 生成 PDF。数据查询与制版可以在同一只读生成脚本内完成，但脚本不得写数据库。
7. 重新打开最终 PDF，完成第8节全部验收。任一项失败都必须修订、重新渲染并复查，不能把“本地能打开”当作合格。
8. 只删除本次创建的 `tmp/pdfs/` 中间文件，不删除历史脚本、历史渲染图或其他用户文件。
9. 最终回复简要报告模型、页数、成交笔数和关键损益，并按 PDF skill 用一次输出文件引用交付成品。

## 8. 强制验收清单

### 8.1 数据验收

- 两个 `strategy_id` 均映射到用户指定的同一 `model_id`。
- PDF 成交行数等于数据库成交行数；各债和合计成交笔数一致。
- 买入/卖出张数、双边成交额、期末库存逐项一致。
- 交易损益、持仓损益、总损益按第3节公式独立复算一致。
- 每笔时间、债券、方向、价格、张数、手数、金额、原因和成交后持仓与数据库一致。
- 数量单位明确为张和手，且1手=10张。

### 8.2 文件与字体验收

- `pdfinfo` 显示 A4 横向、无加密、页数正确。
- `pypdf` 能重新打开文件，关键标题、模型ID、总损益和最后一笔成交时间均能提取。
- `pdffonts` 确认嵌入微软雅黑/微软雅黑粗体和 Arial/Arial Bold 子集；不得出现 DengXian。
- 文件非空，最终路径和文件名符合第6节。

### 8.3 视觉验收

- 用 Poppler 以至少150 DPI把最终 PDF 的每一页渲染为 PNG，并逐页查看，不得只看第一页。
- 检查标题、指标卡、标的卡、摘要、表头、每一列、页眉、页脚和页码。
- 不得出现文字截断、重叠、乱码、黑方块、字体回退、列错位、行越界、金额小数缺失或最后一行被页脚遮挡。
- 与最近批准基准并排检查：字体家族、数字字形、粗细、字号层级、行距、列宽、颜色和边距应保持一致。

## 9. 安全与边界

- 本流程只读市场数据库并生成本地报告，绝不导入或调用 `xttrader`，不发送任何真实委托。
- `output/` 和其中 PDF 均为本地输出，不得 `force-add` 到 Git。
- 生成日报不授权修改策略规则、模型实现、账户账本或模型注册表。若发现数据或模型身份冲突，停止制表并报告，不得为了让报表好看而改账。
- 不得用当前配置或当前模型倒写历史模型的交割单；历史报告必须查询当日保存的模型指派和独立账户。
