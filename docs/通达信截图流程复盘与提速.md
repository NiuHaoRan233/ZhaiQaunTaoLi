## 下次固定流程

1. **启动只读必要文档。** 目录AGENTS、仓库采集技能、完整逐页参考和Computer Use当前规则。先检查当日图是否已存在；存在就整理，不重新操作客户端。本复盘仅故障排查时查阅。
2. **一次校准。** 发现并选中实际通达信窗口，核对证券代码和名称；确认左下“资金流向”右边入口、右下“细”和明细栏数。坐标不跨布局硬套。
3. **连续截图。** 导入并配置正式helper。每只先后完成委托、成交，各自PageUp到首界、PageDown逐页立即保存、稳定数据哈希确认末界。每次输入后有新观察，不连续盲翻；不逐页向模型输出大图，不为时间命名打断截图。
4. **即时交付截图节点。** 报告两只各页数、保存位置和“从窗口发现到最后截图”的实测时间。约60秒是客户端已打开、连接正常、布局稳定时的目标，尚不是已完成的端到端性能认证。
5. **离线一次识别。** 当前八栏委托传`--panels 8`；两类均传`--cache-dir`。截图落盘后不再为了OCR错误切回通达信。缓存放在本地忽略目录，重试CSV写新目录。
6. **集中验收和复核。** 先核对总笔及页边界、满栏/空栏，再看低置信和格式异常、重叠不一致。裁剪一批带上下文的原图来复核。修正写侧表，重复解析用缓存；不要启动新一轮全图OCR解决同一个字段解析错误。
7. **一次写最终索引。** 写明原图映射、总笔、重叠、修正、首选读取文件和剩余问题。截图边界完整且所需复核全部解决后，才设置自动分析可用。最后保留组合分时页。

当前2560×1392实测满栏委托77行、成交75行，只是本次布局的验收参考，不是所有分辨率的固定值。
末栏不足或空栏正常。全天最早最晚时间以客户端真实记录为准，不强行截成09:30—15:00；委托可能含09:15竞价和15点后记录。

## 正式命令与重试方法

以下路径从仓库根目录解析。`<新输出目录>`必须与已复核正式输出区分。

```powershell
.\.venv\Scripts\python.exe -m zhaiquant tdx-extract-orders --input-dir <委托图片目录> --date <YYYY-MM-DD> --code <证券代码.SH> --panels 8 --cache-dir 成交委托数据截图保存/.ocr-cache --output-dir <新输出目录>
.\.venv\Scripts\python.exe -m zhaiquant tdx-extract-trades --input-dir <成交图片目录> --date <YYYY-MM-DD> --code <证券代码.SH> --cache-dir 成交委托数据截图保存/.ocr-cache --output-dir <新输出目录>
```

改解析逻辑后重复相同输入和缓存目录，使用另一个新输出目录。
摘要中的`ocr_cache_hits`和`ocr_cache_misses`说明实际是否复用。
缓存保存裁剪前后流程中的**原始面板OCR token**：面板图已经裁剪，token尚未按解析器规范缩放横坐标。
缓存按图像内容、尺寸和RapidOCR版本区分；不把旧日期文件名当成内容一致的依据。

原始token与人工纠正各自保留；缓存不会自动应用人工纠正，也不会代替原图。
买单/卖单栏合并单元格的空字段不是零，不能为了让CSV“完整”而逐笔重复填充合并总量。
