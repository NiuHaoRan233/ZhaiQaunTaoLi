## 原因与修复

原0.16研究入口要求全局市场时间严格递增，真实接收中四只证券的最新报价时间却可以不同。09-07四次跨证券市场时间回退中，三次来自同一启动快照批次，不能都称为网络延迟。这是输入与恢复合同不匹配，不是观察正股走势本身有问题。

专用实现 `src/zhaiquant/shared_thousand_maker_v016_live.py`：

1. 按实际处理顺序推进，保留源市场时间和原接收时间。决策时间取前次决策时间、本次源市场时间、接收时间三者最大值，不事后排序或改写raw行情。
2. 旧被动单先结算，但下单决策时间必须严格早于成交源市场时间；晚到的旧成交不能填后来挂的单，新评分也不能否决已触发的旧单成交。
3. 主动五档容量按源行情时间分桶，同时间戳不能重复消费；报价比决策时钟落后超过已有`qmt.stale_after_seconds`（本机3秒）时，不提供主动可执行深度。
4. 同证券源时间或累计量回退仅留审计，不覆盖新状态；跨证券较旧源时间正常处理。成交增量用本模型已接受的同证券累计量连续求差。
5. `maker_shared_arrival_days`保存每个模型日执行合同，`maker_shared_arrival_events`追加实际输入及完整快照。重启只按自己的接收日志恢复，不将启用前或后补raw行情插入前向账本；合同变化拒绝原身份重放，错误事件保留并停止该运行时继续交易。
6. 逐日仍按原千张合同独立初始化，不跨日继承。实时采集入口遇昨日报价仅记录raw，隔离累计前序，不送入M0/做市，防止凌晨重启使账户退日或改写昨日日账本。

本身份账本旧字段名`market_ts_ms`表示决策时间，而非交换所成交时间；订单元数据中的源市场时间、接收时间和序号以及原tick引用用于追溯。未改变其他版本的时间字段含义或当日有效交易判断。
