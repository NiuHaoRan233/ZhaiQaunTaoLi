# 实时采集与模拟盘运行手册

版本：2026-09-11

## 1. 系统边界

本程序只使用 `xtquant.xtdata` 读取行情，不使用 `xttrader`，不会向券商发送委托。数据库中的订单、成交和仓位全部是本地模拟记录。

当前 MiniQMT 提供的是 Level 1 tick 快照：最新价、累计成交量/金额/笔数和五档买卖盘。程序可据相邻快照计算盘口变化、成交增量和估计成交方向，但不能获得交易所 Level 2 逐笔委托、撤单明细或真实排队序号。

默认采集范围：

- `132026.SH`：G三峡EB2，参与M0信号和模拟盘。
- `600900.SH`：长江电力，参与M0信号。
- `132024.SH`：额外债券，参与做市纸面研究，不参与M0交易。
- `600362.SH`：132024.SH对应正股，只作为其因果辅助行情和样本外完整性输入，不参与M0交易。

在 `config.toml` 的 `qmt.watch_codes` 中可继续添加债券。额外代码越多，回调压力和数据库增长越快，应观察 `dropped_callbacks`。

## 2. 明日首次运行

建议 08:50 前打开 `D:\东北证券NET专业版`，完成登录并确认行情正常。然后打开 PowerShell：

```powershell
Set-Location -LiteralPath 'E:\QuantProject\债券套利策略'
.\.venv\Scripts\python.exe -m zhaiquant --config config.toml doctor
.\.venv\Scripts\python.exe -m zhaiquant --config config.toml backfill --days 7
powershell -ExecutionPolicy Bypass -File .\scripts\run_live.ps1
```

如果整个项目刚移动到新盘符或新目录，先在新项目根目录执行一次
`powershell -ExecutionPolicy Bypass -File .\scripts\setup_windows.ps1 -SkipDoctor`，用于刷新虚拟环境中的项目定位。根目录下的模拟盘与看板启动器均使用相对路径，不依赖 C 盘固定地址。

`doctor` 必须显示：

- `qmt_connected: true`
- 四个代码均有快照
- `valid_book: true`，集合竞价或停牌阶段偶尔为 `false` 不代表连接失败

`backfill` 可重复运行。第一次会写入数据，之后相同行情应显示 `inserted: 0`。历史 `tickvol` 在 QMT 重读时不稳定，因此原始 JSON 保留它，但去重指纹不使用它。

`run_live.ps1` 会再次执行诊断。诊断成功后，如果本项目同一配置的旧 `zhaiquant run` 仍在运行，脚本会精确结束该旧进程及其 Python 子进程，再在当前窗口前台启动新的长驻进程；不会结束 MiniQMT、`maker-console`、Web 看板或其他 Python 程序。因此也可以直接双击项目根目录的 `start_live.cmd`，把此前隐藏运行的模拟后台替换成当前可见的前台实例。启动时保存一次快照，然后订阅每个代码的 `period="tick"` 回调。窗口必须保持运行；按 `Ctrl+C` 才是正常停止。

## 3. 盘中值守

做市模拟盘可以直接双击项目根目录的 `start_maker_console.cmd` 打开实时看板。两个债券看板只在工作日09:25（开盘前5分钟）至15:30之间检查和刷新：时段内有新模拟成交立即刷新，没有成交时每分钟刷新一次；15:30至次日09:25以及周末不读取数据库、不重建思考快照，窗口保留最后一屏并休眠，下一工作日自动切换日期和恢复。后台行情采集与策略计算不受看板休眠影响。看板显示三峡EB2五档盘口、两个成交口径的现金/库存/持仓方向/盯市收益、当前虚拟挂单及队列、持仓批次和最近模拟成交。它仅以只读方式连接 SQLite；关闭看板不会停止后台行情采集。

后台行情采集进程会按配置顺序实时推进十个候选模型：普通第一顺位1.37、1.50、2.52、2.63、2.70、2.71，以及独立分支千张第一顺位0.1、0.13、0.16（实时修订）和大道至简0.1（实时修订）。内部ID依次为`maker_priority_v1_37_candidate`、`maker_priority_v1_50_candidate`、`maker_priority_v2_52_candidate_r2`、`maker_priority_v2_63_candidate`、`maker_priority_v2_70_candidate_r2`、`maker_priority_v2_71_candidate`、`maker_shared_1000_v0_1_candidate`、`maker_shared_1000_v0_13_candidate`、`maker_shared_1000_v0_16_candidate_r2`和`maker_dadao_v0_1_candidate_r2`。2.63以不可变2.6 r3为直接父版并保持交易行为；2.70使用直接基于2.63的已验证r2，2026-09-07按用户指派追加，不替换原六模型。六个普通模型均按每只债独立账户使用1,000张客户底仓和额外1,000张买入能力，正常库存0—2,000张；三个千张模型各有独立运行时，每个模型内部由两只债共享一块1,000张资金，模型之间不共享资金或状态。旧2.5、2.51、2.6、其余千张共享0.x、queue、Windfall及所有祖先、账户、委托、成交、库存与收益全部保留，不继承或合并；首轮2.70与2.69仍离线。看板只读正式SQLite，不负责运行比较模型。修改实时矩阵后重启后台，六个普通模型及千张0.1/0.13按当日`raw_ticks`确定性恢复；0.16 r2和大道至简仅按各自`maker_shared_arrival_events`接收日志恢复，绝不把启用前或补录行情插回前向账本。凌晨启动收到昨日报价时仅留存原始证据，不推进策略或重置累计前序，不改昨日日账本。进入实时运行不代表晋级。

2026-09-11按用户指派将普通2.71加在2.70之后，保留此前九模型，交易profile及父版2.63不变。新增双债独立普通账户，启用前当日记录由既有启动回放机制生成，实际启用时间见版本登记；不将历史回放当作前向运行。

2026-09-08随后按用户指派追加第九位“大道至简0.1（实时修订）”，ID `maker_dadao_v0_1_candidate_r2`。原八模型保留，它单独使用零底仓、千张（100手）共享槽；与0.16 r2同样按自己的`maker_shared_arrival_events`日志恢复，不回填启用前行情。仅复用原择标，买一买到即跟卖一，卖清再选；日末估值、次日独立重置。详细合同和验证见[大道至简实时接入](大道至简0.1实时接入.md)。

看板顶部的“交易员思考与应对预案”会在每次可见刷新时，根据当时及此前的行情重建当前合理价格、合理区间、价格来源、趋势状态和判断证据，并结合模拟库存与挂单列出当前思路、下一步准备以及向上和向下两套预案。该栏目用于每天核对和纠正模型的看盘逻辑；它是因果、可解释的纸面判断，不连接交易接口，也不会发送真实委托。为避免全天行情反复重放占用资源，持续看板每秒只轻量检查一次是否出现新模拟成交，只有在新成交出现或达到每分钟刷新时间时才重建完整思考快照。

启用`super_windfall_enabled`后，每只做市债券还会增加一个“超级捡漏”独立虚拟账户，实际版本由`super_windfall_model_id`选择；当前前向配置保持关闭。2.0候选固定使用一块1,000张风险容量：相邻买档断层和独立参考折价均至少1元时，在异常下档改善一厘预埋1,000张；卖一折价、卖一到卖二断层均至少1元且卖一完整显示至少1,000张时，可主动纸面买入1,000张。资金按实际成交价派生，买满即停止；正常连续下跌、密集卖盘阶梯、小于1元的断层/折价和不足1,000张的主动供应均拒绝。旧1.0/1.1仍保留2,000元、10张和1.50元折价的不可变历史口径。所有Windfall历史账户均保留，收益不能与普通账户相加；2.0仍只定义发现和买入，退出规则等待后续人工讲解。

看板中的“今日完整交易配对”以每日1,000张期初底仓为基准，把高卖后的买回、低买后的卖出按先进先出配成闭环，展示策略、方向、进出时间与价格、数量、持有时长和毛利润。部分成交会合并并列出明细。“今日尚未闭环交易”单独显示仍待卖出或待回补的数量；“今日全部成交流水”不截断条数，按时间展示当日每一笔模拟成交。

`priority`与`queue`是同一策略的两个独立成交假设账户，不能把收益相加。看板分别建立“第一顺位（乐观成交假设）”和“排队成交（较保守成交假设）”区域，每个区域独立显示账户收益、完整交易、未闭环交易与当日全部流水，不混排成交。

也可以在 PowerShell 中运行一次性或持续看板：

```powershell

.\.venv\Scripts\python.exe -m zhaiquant --config config.toml maker-console

# 输出一次，便于诊断或保存
.\.venv\Scripts\python.exe -m zhaiquant --config config.toml maker-console --once
```

另开一个 PowerShell 窗口：

```powershell
Set-Location -LiteralPath 'E:\QuantProject\债券套利策略'
.\.venv\Scripts\python.exe -m zhaiquant --config config.toml status
Get-Content .\logs\zhaiquant.log -Wait -Tail 30
```

重点检查：

- `latest_session.status`：运行中为 `running`，正常限时结束为 `completed`，异常为 `failed`。
- `ticks`：四个代码的 `count` 应继续增加，`last_ts` 应接近当前市场时间。
- `m0_quality.valid`：盘中应持续增加；大量 `stale_pair` 说明债券与正股快照不同步。
- `dropped_callbacks`：应始终为 0。大于 0 表示队列满，数据库存在不可恢复的实时接收缺口。
- `open_orders`、`open_positions` 和 `paper_strategies`：显示模拟盘状态与累计毛收益。

若 MiniQMT 断线，主进程会主动失败退出，避免无声漏数。重新登录 MiniQMT，先运行 `doctor`，再重启 `run_live.ps1`。重启时：

- 旧模拟挂单会撤销，因为离线期间的真实队列位置无法继承。
- 未平仓模拟仓位会恢复，不会重复开仓。
- 上一交易日遗留仓位会在首个可成交盘口主动退出，并标记 `overnight_recovery`。

同一个数据库仍然只能有一个 `run` 实例。通过 `start_live.cmd` 或 `run_live.ps1` 重启时，脚本会在诊断成功后自动替换本项目同一配置的旧实例；直接绕过脚本启动第二个 `zhaiquant run`，或旧进程不符合安全识别条件时，仍会被 `data/live.lock` 拒绝。

2026-09-11接入2.71实记：14:33:30恢复实时订阅，原九模型保留。首次启动因旧到达合同缺少两个默认关闭字段失败，已增加仅针对已知字段的缺失兼容，原合同和日志未改；仍严格拒绝交易参数变化。新增profile字段时，重启前须用已保存合同核验恢复兼容性；具体证据见版本记录。

15:30 后在运行窗口按 `Ctrl+C`，等待程序写完会话状态并退出。然后执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\backup_data.ps1
```

备份位于 `backups/zhaiquant-日期-时间.sqlite3`。该命令使用 SQLite 在线备份接口，可在数据库开启 WAL 时得到一致文件。不要在主程序运行时只复制 `data/zhaiquant.sqlite3`，否则可能漏掉 WAL 中尚未合并的数据。

## 5. 数据库内容

数据库默认路径为 `data/zhaiquant.sqlite3`。

| 表 | 内容 |
| --- | --- |
| `sessions` | 每次运行、机器、版本、状态和回调丢失数 |
| `raw_ticks` | 市场时间、本机接收时间、成交累计字段、五档价量、原始JSON |
| `tick_changes` | 相邻快照的成交量/金额/笔数增量、买卖方向估计和各档变化 |
| `m0_observations` | 转股价值、局部溢价中位数、可执行偏离和信号状态 |
| `strategy_signals` | M0入场信号及当时价格依据 |
| `paper_orders` | E1-E4模拟订单、限价、排队量、撤单原因 |
| `paper_fills` | 模拟成交价格、数量、参考tick和成交假设 |
| `paper_positions` | 模拟仓位、进出价格、持有结果、最大有利/不利变化 |
| `equity_snapshots` | 每30秒记录的模拟权益 |
| `app_events` | 连接、心跳、异常和恢复事件 |
| `maker_paper_model_assignments` | 每个债券、账户和日期使用的注册模型及父版本 |
| `maker_paper_accounts` | 做市模型独立纸面账户、现金、库存、资金补足和盯市结果 |
| `maker_paper_orders` | 做市委托完整生命周期、撤改原因、队列和模型ID |
| `maker_paper_lots` | 客户底仓、额外仓和回补批次 |
| `maker_paper_fills` | 做市部分/完整成交、参考行情、成交后现金与库存 |
| `maker_shared_arrival_days` | 0.16与大道至简实时修订每个模型日的不可变执行配置 |
| `maker_shared_arrival_events` | 0.16与大道至简实时修订按模型分开的实际处理顺序、原行情与接收时刻；只追加、不以补录重排 |

`inferred_side` 只是本地估计：优先比较成交价与上一快照买一/卖一，其次使用 tick rule。它不能替代交易所逐笔主动买卖标记。

## 6. M0与执行模型

M0 使用最近 1,200 个有效债券观测的转股溢价率中位数，至少预热 600 个。参考值严格使用当前观测之前的数据。

- 入场偏离：以正股买一计算可执行参考价，与债券卖一比较，默认至少低估 `0.8%`。
- 退出偏离：以正股卖一计算参考价，与债券买一比较，默认收敛到 `0.1%`。
- 新开仓：09:35-14:30。
- 最长持有：60个交易分钟；14:55强制退出；退出后冷却10分钟。

执行模型：

- `E1`：主动吃债券卖盘入场，主动打买盘退出。
- `E2`：信号出现后挂买一，等待60秒，退出主动成交。
- `E3`：持续维护满足阈值的预埋买单，退出主动成交。
- `E4`：预埋买单入场，收敛后挂卖一退出，180秒未成交转主动。

E2-E4 同时记录三种成交假设：`optimistic`、`queue`、`conservative`。`queue` 只用可见挂单量和后续成交增量估算排队，无法知道撤单和隐藏队列。结果用于模型间比较，不代表真实可成交收益。

当前收益是毛收益，未扣券商佣金、资金成本和真实滑点。投入实盘前必须按实际费率重新评估，且先积累足够多的模拟成交样本。

## 7. 常用维护命令

```powershell
# 只保存一次快照，不产生模拟成交
.\.venv\Scripts\python.exe -m zhaiquant --config config.toml snapshot

# 限时运行30秒，用于盘前冒烟测试
.\.venv\Scripts\python.exe -m zhaiquant --config config.toml run --duration-seconds 30

# 查看指定交易日
.\.venv\Scripts\python.exe -m zhaiquant --config config.toml status --date 2026-08-11

# 不重新下载，只重读QMT本地缓存并重建衍生数据
.\.venv\Scripts\python.exe -m zhaiquant --config config.toml backfill --days 7 --no-download
```
