# 每日通达信截图整理工作流

本目录是 `132026.SH G三峡EB2` 和 `132024.SH 26江铜EB` 的逐笔委托、逐笔成交截图归档区。用户每天进入本目录时，默认目标是完成当天截图数据的闭环整理；不需要用户重复说明以下惯例。

## 默认任务识别

- 用户说“按惯例整理”“今天图已经截好了”“处理今天的数据”等，均表示：发现两只证券目录根部尚未归档的当日截图，核对后整理为可追溯、可供程序安全读取的数据。
- 先检查截图是否已经存在。若两只证券的截图均已存在，不再打开或操作通达信，直接整理。
- 若截图缺失且用户要求完成每日采集，使用仓库技能 `.agents/skills/tdx-cb-market-capture/SKILL.md`，严格只读采集两只证券。任何 Windows UI 操作还必须遵守该技能指定的 Computer Use 规则。
- 若用户只指定一只证券，只处理该证券；否则每日任务默认包含两只证券。
- 本流程负责采集、归档、OCR、复核和数据质量说明，不自动启动策略回放、修改策略规则或评价模型交易；这些属于另行明确提出的任务。

## 处理顺序

1. 读取仓库级 `../AGENTS.md` 和本文件。涉及通达信采集时，再完整读取采集技能及其完整逐页截图参考。
2. 在每个证券目录根部发现未归档的原始 PNG。以画面内的证券代码、显示名和内部标题为准，不能只按文件名或所在目录猜测：
   - `逐笔委托明细` 归入 `逐笔委托`；
   - `逐笔成交明细` 归入 `逐笔成交`。
3. 使用画面数据所属的实际交易日建立 `<证券>/<YYYY-MM-DD>/`。截屏发生在收盘后或午夜后时，也不能误用截屏日期替代交易日。
4. 保留证券目录根部的原始截图，不移动、不覆盖、不删除。向交易日目录复制标准化副本，并按画面从早到晚连续编号：
   - `YYYY-MM-DD_代码.SH_逐笔委托_01.png`、`_02.png`……
   - `YYYY-MM-DD_代码.SH_逐笔成交_01.png`、`_02.png`……
5. 检查编号从 `01` 连续、首末页确实覆盖画面所示全日、相邻页的重叠或边界可以解释。截图不完整时必须明确标记为“不完整”，不能包装成全日数据。
6. 在主仓库根目录使用项目虚拟环境运行：

   ```powershell
   .\.venv\Scripts\python.exe -m zhaiquant tdx-extract-orders --input-dir <逐笔委托目录> --date YYYY-MM-DD --code <代码.SH> --output-dir <结构化数据目录>
   .\.venv\Scripts\python.exe -m zhaiquant tdx-extract-trades --input-dir <逐笔成交目录> --date YYYY-MM-DD --code <代码.SH> --output-dir <结构化数据目录>
   ```

7. 保留自动生成的 `*_原始识别.csv`、`*_去重.csv`、`*_待人工复核.csv` 和 `*_识别摘要.json`。不得为了修正 OCR 而覆盖原始识别文件。
8. 对 `review_required=True` 的行逐条对照原图：纠正结果写入 `*_人工复核.csv`，再物化 `*_已复核去重.csv` 和 `*_已复核后待人工复核.csv`。无法确认的行继续保留为待复核，不能猜值。
9. 写 `截图索引.md`，逐页记录标准文件、原始文件、首末可见时间、重叠/空白栏/异常情况，并汇总行数、去重数、人工复核数和剩余待复核数。
10. 写 `结构化数据/数据集说明.json`，明确首末时间、首选读取文件、原图是否保留、剩余低置信记录和 `complete_for_unconditional_automatic_analysis`。

## 可用数据判定

- 普通程序优先读取 `*_已复核去重.csv`；若尚未完成人工复核，只能读取 `*_去重.csv` 并显式排除 `review_required=True` 的行。
- 只有逐笔委托和逐笔成交都已完成所需复核、没有遗留待复核记录，并且截图覆盖完整时，才可把 `complete_for_unconditional_automatic_analysis` 标为 `true`。
- 图片是最终审计证据，CSV/JSON 是可追溯的识别结果，不能替代原图。
- `hands` 的单位是“手”，一手等于 10 张债券；不得把手和张混用。
- 委托 `B`/`S` 表示买入/卖出新增委托，`BC`/`SC` 表示买入/卖出撤单。成交方向 `B`/`S` 来自通达信画面，不等同于交易所原生 Level 2 主动方向字段。

## 安全与交付

- 全流程只读行情，绝不导入或调用 `xttrader`，绝不进入交易下单界面，绝不发送券商订单。
- 不提交截图、OCR 结果、`config.toml`、账户数据、日志、SQLite 数据库或备份。
- 根仓库只允许提交本目录的这份`AGENTS.md`工作流；不要使用`git add -f`绕过根
  `.gitignore`上传图片、CSV、JSON或人工复核侧表。
- 不静默覆盖已有正式页或既有人工复核结果；重复处理前先比较，必要时使用清楚标记的重试文件。
- 完成后向用户报告：两只证券各有多少委托页/成交页、结构化行数、去重数、人工复核数、是否仍有待复核项、数据是否可无条件用于自动分析，以及任何不完整边界。
